# Заявки на привет: приём и отказ

Заявку оставляет Чатерс формой на витрине; она уходит админу в Telegram с
номером `#N`. Админ пересылает номер агенту, и агент собирает лот одной
командой. Схема заявок — миграция `20260926130000_submissions.sql`,
статусы меняет только `service_role` через RPC (`20260926150000_submission_accept.sql`).

## Команды

| Команда                                                       | Что делает                                                                                |
| ------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `just submission <id> --check`                                | скачивает видео и собирает медиа-тройку, **ничего не публикует**; безопасный первый заход |
| `just submission <id>`                                        | полный путь: подготовка → Storage → карточка → синк → `accepted`                          |
| `just submission <id> --title "…"` / `--slug …` / `--price N` | ручные переопределения (стартовая цена по умолчанию 800)                                  |
| `just submission <id> --author "…"`                           | ник автора вручную, если резолв по реестру неоднозначен                                   |
| `just submission <id> --force`                                | осознанный обход дубль-гейта после решения человека                                       |
| `just submission-reject <id>`                                 | статус `rejected`, без выплат                                                             |
| `just submission-reject <id> --status duplicate`              | статус `duplicate`, без выплат                                                            |
| `just submission-reward <id>`                                 | повторная выплата награды по уже принятой заявке; идемпотентно                            |

Служебный скрипт — `scripts/submission.py` (см. `--help`); он берёт
`SUPABASE_SERVICE_ROLE_KEY` и `PUBLIC_SUPABASE_URL` из окружения или `.env`,
секреты не печатает.

## Пайплайн приёма (что делает `just submission <id>`)

1. **Чтение заявки** из `public.submissions` по номеру; статус должен быть `new`.
2. **Резолв ника и заголовка**: заголовок берётся из заявки, и заголовок, и
   ник автора канонизируются по реестру `content/chatters.toml` по правилу
   `docs/agents/chatters.md`. Если скрипт заменил написание на канон, он печатает
   подсказку — вариант надо дописать в `aliases` этого ника в
   `content/chatters.toml` (реестр правит человек, скрипт чужой файл не
   перезаписывает). Неоднозначный заголовок или ник автора — стоп: человек
   передаёт готовое `--title "…"` / `--author "…"`.
3. **Проверка на дубликат**: нормализованная ссылка сверяется с `video_url`
   существующих лотов и с `submissions.video_url` уже решённых заявок
   (`accepted`/`duplicate`) — у опубликованных пайплайном лотов в базе Storage-URL,
   поэтому исходник ловится по заявке. Совпала — стоп (см. «Гейты»).
4. **Скачивание** видео по ссылке во временную папку `/tmp/alysque-submission-<id>/`
   (`yt-dlp`; прямая ссылка на файл — запасной `urllib`).
5. **Медиа-тройка** `ffmpeg` по рецепту `docs/agents/media-pipeline.md`:
   `<slug>.webm`, `<slug>.mp4`, `<slug>.webp` (сборка кэшируется в `/tmp`).
6. **Заливка** `scripts/storage_upload.py` в `media/videos/<slug>` (тройка).
7. **Карточка** `[[lots]]` в `content/lots.toml`: `slug`, `title`, `price`,
   `video_url` (публичный URL Storage). Слаг — новый уникальный, привязан к
   заявке: `lot-sub-<login>-<id>`. Id заявки делает слаг уникальным и «своим»:
   повторный прогон той же заявки переиспользует его, разные заявки — даже один
   автор с тем же заголовком — получают разные лоты.
8. **Синк** `scripts/lots_sync.py` — лот появляется на витрине без деплоя.
9. **Связь и статус** — RPC `accept_submission(id, lot_id, author_login)`: заявка
   получает `accepted`, `lot_id`, `decided_at`, а лот — `suggested_by_login`
   (канон ника автора из реестра; не нашли — снимок из заявки) и
   `suggested_by_uid`.
10. **Награда** — RPC `pay_submission_reward(id)`: автору +500 и роялти 3% с первых
    трёх перекупов его лота (тикет 11). Выплата идемпотентна по
    `submissions.rewarded_at`; отказ выплат не делает.

Если приём прошёл, а выплата упала (сеть/5xx), повторный `just submission <id>`
уже не пройдёт — заявка не `new`. Награду добирает `just submission-reward <id>`:
он вызывает только `pay_submission_reward` и повторно не платит благодаря
`rewarded_at`.

После принятия страница лота `/lot/?id=<slug>` показывает «Привет добавил: <ник>»;
в списках витрины подписи нет.

## Гейты «стоп и спроси человека»

Решение об отказе всегда за человеком — команда останавливается (код 2) и
докладывает, **ничего не публикуя**:

- **Мёртвая/приватная ссылка** — `yt-dlp` не смог скачать; файл не создан.
- **Не-привет по смыслу** — определяет агент, посмотрев скачанный клип после
  `--check`. Не похоже на привет из эфира `alysque` — отказ.
- **Дубликат** — клип (ссылка) уже есть на бирже: нашёлся среди `lots.video_url`
  или среди ссылок уже решённых заявок (`submissions.video_url`, статусы
  `accepted`/`duplicate`); отказать как `duplicate`. После решения человека
  гейт можно обойти осознанно: `just submission <id> --force`.
- **Ник автора неоднозначен** — `author_login` заявки совпал с несколькими
  записями реестра: не гадать, спросить человека и передать канон через
  `--author "…"`. Нет совпадений — не стоп: на лот идёт снимок ника из заявки.
- **Ник неоднозначен** — в заголовке нашлось несколько кандидатов реестра:
  не гадать, спросить человека и передать готовый заголовок через `--title "…"`.
- **Нет в реестре** — предупреждение: сверить написание вручную по
  `docs/agents/chatters.md` (при однозначном варианте дописать `aliases`).

Рабочий порядок агента: `show` → `--check` → осмотр клипа → полный проход или
`submission-reject`.

## Отказ

`just submission-reject <id>` ставит `rejected`/`duplicate` и `decided_at`,
выплат не делает. Отказ по принятой заявке запрещён (лот уже на витрине);
повторный отказ по уже решённой заявке — no-op (`заявка уже решена`).
Отклонённая заявка на витрине не появляется.

Решение принимает только открытая заявка (`status = 'new'`): и
`accept_submission`, и `reject_submission` меняют строку с предикатом
`status = 'new'` и падают с ошибкой, если заявка уже решена — двойное решение
или перезапись чужого решения сервер не пропускает.
