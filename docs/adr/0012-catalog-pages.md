# Каталог — срез страницы: страницы витрины, случайная выборка, один лот

`/lots/` читает каталог страницами по 12 в порядке «дешёвые → дорогие», а не целиком (витрина остаётся клиентской проекцией БД — ADR 0002). Страница читается keyset-курсором по паре `(price, slug)`: цена меняется от перекупов, slug добивает ничью и держит границу на месте — offset бы сдвигался живыми вставками и ростом цен. Снапшот живых данных (ADR 0003) в этом режиме хранит загруженное окно: тик `lots` освежает окно одним запросом по slug, удалённые уходят, а лот из Realtime вставляется, только если по цене попадает в окно; дороже границы — ждёт своей страницы. Уже показанные карточки не переезжают, как и раньше.

Срез — свойство страницы, а не глобальное: `/lots/` листает страницы, главная читает случайную выборку из вью `public.random_lots` (`order by random()`, клиент берёт первые N), страница лота — один лот по slug. Полный каталог не читает никто. Колоколу на всех страницах нужны «Мои приветы»: `initOutbidNotice` включает `trackMyLots` — отдельный полный запрос владельца, а не фильтр окна, иначе лоты с дальней страницы пропадали бы, а перекуп по ним не долетал бы до колокола. Возврат из логина к лоту с дальней страницы дочитывает страницы до него (`ensureCatalogLot`), иначе модалка покупки не нашла бы кнопку.

Механика листания — чистое ядро `src/lib/catalog-page.ts` (порядок, курсор, граница окна, склейка, вставка; тесты рядом). Случайная выборка обновляется тем же окном по slug: новые лоты её не добирают, удалённые уходят. «История перепродаж» осталась на своём ядре `trade-history.ts` с кнопкой «Показать ещё»: у неё ключ неизменяемый, а у витрины цена живая и есть граница окна — общий код ради десяти строк не выводим. Под страницы — миграция с индексами `lots(price, slug)` (курсор) и `lots(owner_uid)` (мои лоты); случайная выборка — вью `public.random_lots` (обёртка `lots_with_next_price` в случайном порядке, гранты — в той же миграции).

## Considered Options

- **Только порционный рендер** (каталог читается целиком, сетка рисует по 12): без риска для снапшота, но не решает главную боль — полную выгрузку и полное перечитывание каталога на каждый тик при росте.
- **Offset-пагинация** (`range`): проще, но живые вставки и рост цен сдвигают границы — строки дублируются и теряются.
- **Keyset по `(created_at, id)`** (как в истории): стабильно, но ломает порядок «дешёвые первыми» — новичок первым делом должен видеть доступные лоты.
- **Одно общее ядро листания с историей**: у истории ключ неизменяемый, у витрины цена живая и окно имеет границу; параметризация ради двух мест дороже дублирования десяти строк.
- **Окно на всех страницах**: главной нужен случайный лот из всего каталога, странице лота — один лот; общий неполный снапшот сломал бы обе — поэтому срез свой у каждой поверхности.
- **Случайные на клиенте из полного каталога**: выбор в браузере оставлял полную выгрузку и полное перечитывание на каждый тик — главную боль, ради которой всё делалось; отклонено.
