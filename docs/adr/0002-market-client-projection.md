# Витрина и страницы лотов — клиентская проекция БД

Витрина `/lots/` и страница лота `/lot/?id=<slug>` строятся в браузере из Supabase: на билде в HTML нет ни карточек, ни страниц лотов, а Realtime добавляет/убирает/обновляет карточки. Публикация контента — `just lots-sync` без деплоя; билд не ходит в БД (но требует `PUBLIC_SUPABASE_*`, чтобы ключи уехали в бандл). Старые адреса `/lots/<slug>/` не поддерживаются.

## Considered Options

- **SSR** (`output: 'server'` + адаптер): настоящая динамика и код 200 на любой путь, но требует хостинга с сервером — переезд с GitHub Pages.
- **Чистый SSG** (было): набор карточек и существование страницы лота фиксировались на билде; новый лот появлялся только после пересборки и деплоя.
- **Гибрид** (SSG-сиид известных лотов + 404-роутер для новых): сохраняет первый экран, красивые URL и старые ссылки, но новый лот отдаётся с кодом 404, а у деталки появляются два пути (статический и клиентский).

Выбран клиентский рендер: на статическом хостинге единственный способ дать лоту, которого не было на сборке, настоящую страницу — унести идентификатор в query на существующий файл. Первый экран и SEO лотов принесены в жертву ради публикации контента без деплоя.
