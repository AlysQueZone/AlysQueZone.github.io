# Цикл окна — один модуль: `src/lib/modal.ts`

Открытие, закрытие, Escape, клик по затемнению и фокус — один цикл на четыре окна: покупка (`BuyModal`), гамба, правила биржи и окно ежедневного входа. `createModal(dialog, hooks)` возвращает handle (`open(opener?)`/`close`); компонент объявляет разметку и своё состояние в `onOpen`/`onClose`, а `opener` (для программных кликов) задаёт, куда вернуть фокус.

Цикл стоит на нативном `<dialog>`: `showModal()` даёт top layer, инертность фона, удержание фокуса, Escape и back-жест, `::backdrop` и возврат фокуса. Модуль владеет только тем, чего `<dialog>` не даёт: контрактом `data-modal-close`, явным opener'ом (Safari не фокусирует кнопку кликом, поэтому нативный возврат туда не попадёт), фолбэком клика-вне для браузеров без `closedby` и хуками. Первый фокус — `autofocus` в разметке. Роль, `aria-modal`, ловушку Tab и стек модуль не дублирует: это регресс, а не забота поверхности.

Escape одного окна — нативный. Исключение — два открытых окна: Chrome шлёт close request обоим, если нижнее открыли без user activation (например, возврат из логина), и cancel нижнего не отменяется. Модуль в capture гасит default и закрывает только верхнее; без этого одно нажатие гасило бы и покупку, и всплывшее окно входа.

Контракт разметки: корень — `<dialog class="modal-dialog" closedby="any">` с `aria-labelledby`/`aria-label`; кнопки закрытия носят `data-modal-close`; клик по бэкдропу закрывает окно. `closedby` — прогрессивное улучшение: в Safari его нет, там фолбэк `pointerdown`/`pointerup` проверяет координаты (цель клика по бэкдропу и паддингу — сам `<dialog>`). Слушатель кнопок — на корне, а не на `document`: клик, которым окно открыли, в него уже не попадёт.

Открытые окна живут нативным стеком top layer: Escape, Tab и клик-вне обслуживают верхнее; нижнее окно не снимаем. Так автоматическое окно ежедневного входа всплывает поверх открытой покупки и не отбирает у неё управление. `hasOpenModal()` — `document.querySelector('dialog[open]')`: поверхности со своим Escape (колокол, `docs/adr/0005`) уступают клавишу. Программный `close()` синхронно возвращает фокус и зовёт `onClose`; нативный `close`-event (Escape, бэкдроп) делает то же через guard, чтобы хук не сработал дважды.

Скролл: `.modal-dialog` — сама карточка (`card-pixel`) и scroll-контейнер с `overscroll-behavior: contain`; `::backdrop` — `overflow: hidden` и `contain`. Иначе прокрутка над бэкдропом или внутри окна уходила бы на страницу под ним.

## Considered Options

- **Четыре копии на местах** (было): цикл дублировался в `BuyModal`, `GambaModal`, `RulesModal` и окне входа; мелочи (набор классов, aria, порядок фокуса) расходились, и расхождения никто не ловил.
- **Одно окно на страницу** (открытие нового закрывает прежнее): автоматическое окно входа закрывало бы открытую покупку и теряло её намерение — стек честнее.
- **`modal-focus.ts` плюс оркестратор снаружи**: два владельца одного цикла — Escape и клик-вне остались бы у компонентов, расхождения продолжались бы.
- **Делегированное открытие `data-modal-open`**: у окон разные точки открытия и разное содержимое (намерение покупки, живые строки гамбы) — открытие осталось у компонентов, модуль владеет только циклом.
- **Нативный `<dialog>` без обёртки**: компоненты сами звали бы `showModal()` и повторяли `data-modal-close`, фолбэк клика-вне и возврат фокуса — расхождения вернулись бы. Обёртка оставляет один вход.
- **Самописный цикл поверх `<dialog>`** (держать `role`, Tab-ловушку, Escape на `document`): дубль платформы; нативный модал уже инертен, держит фокус и умеет back-жест.
