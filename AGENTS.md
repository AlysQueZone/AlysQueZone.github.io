# AlysQueZone

Шуточная биржа приветов Twitch-канала alysque. Запуск — README.md.

- Коммить сам, когда изменение готово; новые решения — краткой строкой сюда.
- README — простая инструкция для человека, без подробностей.
- Документы в `docs/` и `scratch/` — задача агента: поддерживать актуальность; устаревшие изменять или удалять на своё усмотрение.
- Гейт красный — деплоя нет: `npm run build` + клик сборки в `preview`.
- Бэкенд — в Supabase, схему — только миграциями; контент лотов — `content/lots.toml` + `just lots-sync` (не миграциями).
- Новая таблица → в той же миграции гранты `anon`/`authenticated`/`service_role` и `usage` на sequence (с 30.10.2026 автоматом не выдаются); шаблон — `docs/agents/supabase.md`.
- Витрина и страницы лотов — клиентская проекция БД (`docs/adr/0002`): контент публикует `just lots-sync` без деплоя; билд без запроса к БД, но требует `PUBLIC_SUPABASE_*`.
- Математика биржи — из одних рук: меняешь механику — обнови витрину и `CONTEXT.md`; серверный рост цены — одна функция `public.next_lot_price` (`docs/adr/0007`).
- Баланс — один поток: подписка BaseLayout транслирует `alysque:balance`; намерение покупки и правило «не хватает Пивкойнов» — в `src/lib/buy-intent.ts` (гейт всё равно серверный).
- Живые данные — один владелец: Realtime-каналы открывает только `src/lib/live.ts` (реестр, реф-каунт); в компонентах и страницах `sb.channel()` не зовём — `docs/adr/0003`.
- Тесты ядра — `just test` (vitest, без DOM): реестр живых подписок и чистая логика; pre-commit гоняет их вместе с lint-staged.
- Ошибки транспорта — один классификатор (`src/lib/errors.ts`): текст, офлайн, нет входа; доменные виды — у своих мапперов.
- Загрузка — скелетонами (`.skeleton-block`), не текстом-заглушкой; бегущая строка меняет контент под fade, чтобы не дёргалась.
- Всплывающие уведомления — один модуль (`src/lib/notice.ts`): стек, таймеры, крестик и медиа там; вызывающий говорит только «что показать».
- Окна-диалоги — один цикл (`src/lib/modal.ts`): Escape, клик-вне, фокус-ловушка и стек окон там; компонент объявляет разметку (`data-modal-close`) и состояние в `onOpen`/`onClose` — `docs/adr/0008`.
- Карточка Лота — одно представление (`src/lib/lot-view.ts`): слоты и раскладка кадра там; поверхность даёт корень и состояние, свои поля (title документа, автор, сортировка) правит сама — `docs/adr/0009`.
- Цвет/визуальный стиль — один источник: палитра D1 в `design-system/alysquezone/MASTER.md`, токены — `@theme` в `src/styles/global.css`; hex в коде не хардкодим.
- Контраст — часть стиля: muted-текст только `text-mist` (без `/60…80`), акцентный текст — `*-deep` или затемнённый токен (`melon`, `pivko`); проверка — `validate-tokens.cjs`.
- UI/UX-скиллы (`.opencode/`) в гите нет: свежий клон — `npx uipro init --ai opencode`, обновление — `npx uipro update`.

## TODO.md, NOTES.md и CHANGELOG.md

- `TODO.md` — общий бэклог: `## Планы` (открытые задачи) и `## Абстрактные идеи` (задел человека, агент не берёт). Пишут оба: человек — задачи и идеи; агент — конкретные хвосты своей работы и технический долг (отложенная проверка, баг вне скоупа, нерешённая мелочь) строкой в тематическую секцию `## Планы`. Продуктовых идей агент не добавляет.
- Задачу выбирает человек — агент сам из списка не начинает; автономный цикл — только по явному разрешению сессии (например, в хендоффе).
- `NOTES.md` — произвольные заметки (мемы, задел): не бэклог, задачи оттуда агент не берёт и сам не дописывает.
- Перед добавлением пункта — проверить дубли; за одну работу не больше пары строк; формулировка самодостаточная (без ссылок на удалённые спеки).
- Запись в `CHANGELOG.md` — сначала задача словами человека, как он её написал (прямая просьба без пункта в бэклоге — тоже запись, формулировка из просьбы). Ниже при необходимости — `→` комментарий агента.
- В ченджлог идёт только изменение проекта: продукт или правила. Проверки и аудиты («проверь», «разберись», «посмотри») — не изменение: даже если по ходу поправил свои доки, скиллы или пайплайны, запись не делаем. Сомневаешься — спроси человека.
- Закоммиченное изменение попадает под `## Внесённые изменения`; закрытый пункт `## Планы` уходит.
- Невыполненный пункт агент не удаляет: если он устарел или спорен — спроси человека.
- `just release` → `## Внесённые изменения` переименовывается в `## YYYY-MM-DD HH:MM — тема` (время московское, `Europe/Moscow`), сверху создаётся пустая секция; свежее всегда сверху.
- Контент лотов (`just lots-sync`) в ченджлог не пишется — только убирается пункт из планов.
- Статусов и «не будем» нет: сделал — перенёс, передумал — удалил пункт.
