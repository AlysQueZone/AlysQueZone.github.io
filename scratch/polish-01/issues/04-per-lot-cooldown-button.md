# Перезарядка на лот с честным таймером на кнопке

Type: grilling
Status: resolved
Blocked by: 03

## Question

Человек решил: перезарядка — только на тот же лот (per-lot 30с), разные лоты можно покупать без задержки; глобальный кап 10 покупок/10мин остаётся как антиспам. Где и как это видно: таймер обратного отсчёта прямо на кнопке покупки с реальным серверным значением (не локальный fake-таймер), плюс всплывающее уведомление «подожди N сек» при попытке раньше времени? Решить: источник правды таймера (last_buy из shared-истории vs server error countdown vs Realtime-event), поведение при гонке (чужой выкуп сбрасывает ли мою перезарядку), текст кнопки в трёх состояниях (можно / жди N с / кап окна), нужен ли триггер-миграция с per-lot на per-(user,lot) вместо текущего глобального per-user. Заблокировано терминологией (03): без новых слов тексты не фиксируем.

## Answer

Механика (всё рекомендованное, принято 2026-09-07): (1) мигрировать триггер `enforce_purchase_rules` с per-user на **per-(user,lot)** 30с — проверка «моя последняя покупка этого лота < 30с», иначе «разные лоты без задержки» не работает; кап 10/10мин остаётся глобальным антиспамом; (2) таймер на кнопке — **проекция из shared-истории** (моя последняя покупка этого лота, живо через Realtime) + серверная ошибка с retryAfter как подтверждение правды; (3) **чужой выкуп мой кулдаун не трогает** — только меняет цену и показывает уведомление «забрал X за N — забрать за N+10%?»; (4) три состояния кнопки: «Забрать за N 🍺» / «Жди N с» (disabled + живой отсчёт) / «Лимит: 10 покупок за 10 минут» (disabled).
Тексты (поправка Q5, выбор делегирован агенту): в UI слова «кулдаун»/«передышка» нет — только **«Жди N с»** на кнопке и **«Подожди N с — этот лот можно забрать повторно через N с»** в уведомлении; существительное **«пауза»** — лишь там, где без существительного не обойтись. С человеком общаемся словом «кулдаун».
