# Карта: Предложить привет

## Destination

Спека `scratch/suggest-greeting/spec.md` для функционала «Предложить привет»: чатерс, вошедший через Twitch, предлагает привет (название, ссылка, опциональный комментарий); заявка с человекочитаемым id (`#N`) уходит админу в Telegram; админ по id запускает агента, который собирает карточку лота; за принятую заявку отправитель получает +500 и 3% с первых 3 перекупов. Реализация — тикетами [`issues/08…12`](issues/), frontier — [08](issues/08-submission-intake.md).

## Notes

- Эффорт планирует: резолвим решения, спека — закрывающий артефакт; кода фичи в этом эффорте нет.
- Термины — из `CONTEXT.md` («Чатерс», «Привет», «Лот», «Пивкойн»); новые понятия («Заявка», «Награда за принятый привет») решены в тикете 05 и уезжают в `CONTEXT.md`.
- Правила проекта: математика из одних рук (меняешь механику — обнови витрину и `CONTEXT.md`); денежный гейт серверный; схема — только миграциями с грантами по шаблону `docs/agents/supabase.md`; контент лотов — `content/lots.toml` + `just lots-sync`.
- Админ — владелец проекта: решения по месту в UI, экономике и текстам — за ним (HITL).
- Скиллы по тикетам: `research` (AFK, отчёты в `scratch/suggest-greeting/research/`), `prototype`, `grilling` + `domain-modeling`.

## Decisions so far

<!-- индекс: одна строка на закрытый тикет -->

- [Telegram-уведомление: транспорт, секреты, деплой](issues/01-telegram-transport.md): рекомендация — триггер на заявках → pg_net + секреты в Vault (at-most-once, без новых деплоев); Edge Function + Webhook — альтернатива при росте логики.
- [Приём видео: безопасная загрузка в Storage](issues/02-video-upload-safety.md): рекомендация v1 — только ссылка (allowlist хостов, скачивает агент локально); если файлы — приватный бакет `submissions` + RLS «своя папка», MIME/размер — не безопасность, реальная проверка — `ffprobe` + человек при принятии.
- [Прототип: место «Предложить привет» и форма](issues/03-ui-prototype.md): выбран вариант E — инлайн-секция внизу витрины (слева форма, справа инфо: инструкция, пивкойны, авторство), спрятана за тихой ссылкой; в v1 только ссылка, без загрузки файла.
- [Экономика награды за принятую заявку](issues/04-bonus-economy.md): +500 сразу при принятии и 3% с первых 3 перекупов из комиссии (7% = 4% сгорает + 3% автору); дубликаты не платятся дважды; лимит — 10 открытых заявок разом; тонкости в UI не выносим.
- [Домен и схема заявок: термины, статусы, приём файлов](issues/05-submission-domain.md): таблица `submissions` (id `#N`, автор, название, ссылка, комментарий, статус, `lot_id`, `rewarded_at`, `notified_at`) + прямой insert под RLS и BEFORE-триггер (https, allowlist хостов, лимит 10 открытых на чатерса); статусы только через `service_role`; автор денормализуется на лот для подписи «Привет добавил: <ник>» (только страница лота); уведомление о принятии — всплывашкой с серверной меткой `notified_at`.
- [Сообщение в Telegram и пайплайн агента «id → карточка»](issues/06-telegram-message-and-agent-pipeline.md): сообщение с `#id`, названием, ником, ссылкой и комментарием (без превью); пайплайн `just submission <id>` / `just submission-reject <id>` в новом `docs/agents/submissions.md`; отказ решает человек.
- [Спека «Предложить привет»](issues/07-spec.md): собрана в [`spec.md`](spec.md) — сценарий, UI, схема, экономика, Telegram, пайплайн агента, края и не-цели; вход для `to-tickets` / `implement`.

## Out of scope

- Мини-админка на сайте и Telegram-бот с кнопками — админ решает вручную, карточку по id собирает агент (выбор владельца).
- Анонимные заявки без логина — награде нужен адрес, RLS пишет только от своего uid (выбор владельца).
- Награда поприветствованному чатерсу — награда идёт отправителю заявки; вернуться, если появится связка «ник ↔ uid».
- Публичная очередь и голосование за заявки.
- Автоматическое принятие заявки без человека.
- Универсальный центр уведомлений (колокольчик по всем событиям, а не только перекупам) — в проекте его нет; встраивание в существующий колокольчик перекупов — отдельный рефактор. Уведомление о принятии — всплывашкой с серверной меткой.
