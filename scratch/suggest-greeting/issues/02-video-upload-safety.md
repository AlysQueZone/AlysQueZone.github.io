# Приём видео: безопасная загрузка в Storage

Status: resolved
Type: research
Blocked by: none

## Question

Можно ли безопасно принимать от чатерсов небольшие видеофайлы напрямую в Supabase Storage, и какие есть варианты?

- Сейчас: бакет `media` публичный (лимит 25 МБ, MIME: webm/mp4/webp/mpeg), RLS на `storage.objects` нет, заливка только `service_role`-скриптом из корня репо; загрузки из браузера нигде нет.
- Разобрать: signed upload URL / `createSignedUploadUrl` + `uploadToSignedUrl`, RLS-политики на `storage.objects`, приватный бакет для заявок, лимиты размера и MIME на бакете, проверка настоящего типа содержимого (спуфинг `content-type`), сроки жизни URL, удаление и очистка, бесплатные лимиты Storage и стоимость.
- Сравнить с альтернативой «в v1 загрузки нет — только ссылка».
- Ответ: варианты с плюсами и рисками + рекомендация + что попадает в схему и спеку.

## Answer

Разбор: [`research/video-upload-safety.md`](../research/video-upload-safety.md).

- **Рекомендация для v1 — загрузки нет, только ссылка** (вариант c): Storage не трогаем, инвариант «заливка только `service_role`-скриптом» сохраняется, исходник агент и так добывает локально при принятии. Если файлы всё же нужны — вариант (a): приватный бакет `submissions` с RLS «только своя папка» (`<uid>/...`), без signed URL и без Edge Function.
- **MIME и размер — не безопасность**: `allowed_mime_types` проверяет объявленный клиентом `Content-Type`, magic bytes Storage не смотрит; реальная проверка «это видео» — `ffprobe` + человек при принятии. Поэтому файлы до принятия — только приватный бакет, никогда не публичный `media` (публичное навсегда не убрать аккуратно).
- Signed upload URL устроен безопасно (токен привязан к конкретному пути, живёт 2 часа, право проверяется на выдаче), но для нашей формы не обязателен: хватает прямого `upload()` с RLS INSERT на свою папку. Для upsert нужны INSERT+SELECT+UPDATE, нам upsert не нужен.
- Лимиты free: 50 МБ на файл, 1 ГБ хранилища, 5 ГБ egress; 40 файлов по 25 МБ забивают хранилище. Удаление файлов — **только через Storage API** (`service_role`): SQL-`DELETE` по `storage.objects` оставляет байты в S3 и тарифицируется.
- Ссылки: `new URL` + https + allowlist хостов (`clips.twitch.tv`, youtube/youtu.be, streamable, medal, vkvideo, `cdns.memealerts.com`), нормализация; приложение само по ссылкам не ходит — скачивает агент локально при принятии, SSRF в проде нет.
- Решение «ссылка или файлы в v1» — за тикетом [Домен и схема заявок](05-submission-domain.md).
