# 09: Заявка приходит админу в Telegram

Status: ready-for-agent
Blocked by: 08
Спека: [`spec.md`](../spec.md)

## What to build

Каждая новая заявка отправляет админу сообщение в Telegram с номером, названием, ником, ссылкой и комментарием — номер первым, чтобы его можно было переслать агенту. Секреты бота живут только на сервере; сбой отправки не мешает заявке сохраниться.

## Acceptance criteria

- [ ] Триггер на вставку заявки шлёт сообщение формата из спеки (без превью ссылки; комментарий — строкой, только если есть).
- [ ] Токен бота и chat_id лежат в Supabase Vault; в git не попадают; есть runbook настройки и ротации.
- [ ] Ошибка отправки не откатывает заявку; локально без секретов уведомление тихо не отправляется.
- [ ] Человеческий шаг выполнен: бот создан, `/start` нажат, chat_id получен, секреты в Vault.
- [ ] Проверено: живая заявка → сообщение в Telegram; при недоступном Telegram заявка остаётся в базе.

## Comments

- Реализовано в коммите `2426d5c`: миграция `supabase/migrations/20260926140000_submission_telegram.sql` (pg_net в `extensions`, схема `private`, `security definer`-функция `private.notify_submission_telegram()` с `search_path = ''`, `after insert`-триггер `trg_submissions_notify_telegram`; формат из тикета 06, превью ссылки отключено, сбой — `warning` без отката заявки, без секретов — тихий no-op) и runbook `docs/agents/telegram-notify.md`.
- Человеческий шаг остаётся за владельцем: завести бота у @BotFather, нажать `/start`, получить chat_id и положить `telegram_bot_token` + `telegram_admin_chat_id` в Vault — без этого уведомления молчат. Проверка живой заявкой против прод-Telegram не выполнялась (интеграция БД проверяется централизованно позже, как и в тикете 08).
- Ревью: убран необязательный алиас `telegram_chat_id` — функция читает только канонические `telegram_bot_token`/`telegram_admin_chat_id` одним проходом по `vault.decrypted_secrets`; runbook приведён в соответствие (имена фиксированы, без алиаса), в диагностику добавлены `net.worker_restart()`/`net.wait_until_running()` (лёгший воркер pg_net теряет сообщение молча), предупреждение об обрезке пробелов/переводов строк у скопированных `token`/`chat_id` и шаг `getMe` после ротации.
