# 10: Агент собирает лот из заявки (принятие и отказ)

Status: ready-for-agent
Blocked by: 08
Спека: [`spec.md`](../spec.md)

## What to build

По номеру заявки админ одной командой принимает привет: агент скачивает видео по ссылке, проверяет, что это по смыслу привет, готовит медиа-тройку и карточку, публикует лот на витрине, связывает его с заявкой, пишет автора и ставит статус «принята». Отдельная команда фиксирует отказ или дубликат без выплаты. При проблемах агент останавливается и спрашивает человека. На странице принятого лота появляется подпись «Привет добавил: <ник>».

## Acceptance criteria

- [ ] `just submission <id>` проходит весь путь: заявка → скачанное видео → медиа по существующему пайплайну → карточка в контенте → синк → связанный лот на витрине.
- [ ] Заголовок берётся из заявки с резолвом ника по реестру, слаг — новый уникальный.
- [ ] Заявка получает статус «принята», связь с лотом и автора; страница лота показывает «Привет добавил: <ник>», в списках витрины подписи нет.
- [ ] `just submission-reject <id>` ставит «отклонена» или «дубликат»; выплат не делает.
- [ ] Пайплайн описан документом для агента + указатель в `AGENTS.md`; при мёртвой ссылке, не-привете или дубликате агент останавливается и докладывает.
- [ ] Проверено: принятая заявка видна как лот с подписью; отклонённая не появляется.

## Comments

- Реализовано в коммите `6045aef`: миграция `supabase/migrations/20260926150000_submission_accept.sql` (колонки `lots.suggested_by_uid/_login`, пересоздание вью `lots_with_next_price` через `DROP VIEW + CREATE`, RPC `accept_submission`/`reject_submission` только для `service_role`; награду не начисляет — тикет 11), пайплайн `scripts/submission.py` и рецепты `just submission` / `just submission-reject`, подпись «Привет добавил: <ник>» на странице лота (`src/lib/lots.ts`, `src/pages/lot/index.astro`), документ `docs/agents/submissions.md` и указатели в `AGENTS.md`.
- Гейт «стоп и спроси человека» — флаг `--check` (скачать и собрать медиа, ничего не публикуя), авто-остановка на мёртвой/приватной ссылке и на дубликате по ссылке, остановка на неоднозначном нике; отказ — `just submission-reject <id> [--status duplicate]`.
- Отложено: SQL-проверки RPC против локального Supabase (по указанию тикета `supabase start`/`db reset` не запускал — проверка централизованная); награда +500 и роялти — тикет 11.
- Правки по ревью: вью `lots_with_next_price` снова получает грант `service_role` (терялся при `DROP + CREATE`); слаг привязан к заявке — `lot-sub-<login>-<id>` (иначе две заявки одного автора с одинаковым заголовком схлопывались в один лот); дубль-гейт дополнительно ловит повторную ссылку по `submissions.video_url` уже решённых заявок (`accepted`/`duplicate`), а не только по `lots.video_url` со Storage-URL; `accept_submission`/`reject_submission` меняют строку только из статуса `new` (предикат на сервере, а не только в клиенте — доки не врут); при замене написания ника на канон скрипт печатает подсказку дописать вариант в `aliases` (`content/chatters.toml` правит человек).
- Правки финального сквозного ревью: нормализация ссылки в дубль-гейте приведена к серверной (`normalized_url` сохраняет query, выкидывая только `utm_*`/`si`/`igsh`) — иначе `watch?v=AAA` и `?v=BBB` ложно считались одним клипом и гейт блокировал любые две YouTube-заявки; добавлен `--force` для осознанного обхода дубль-гейта; ник автора резолвится по реестру `content/chatters.toml` и передаётся в `accept_submission` новым параметром `p_author_login` (US-24), неоднозначность — стоп с подсказкой `--author`; явный `--slug` проверяет коллизию и по `content/lots.toml`, а не только по БД (мёртвый параметр `manifest` убран); комментарий про «непубличность» `suggested_by_uid` приведён в соответствие (таблица `public.lots` читается `anon`/`authenticated`, uid виден как `owner_uid`); `20260926170000_submission_notified.sql` получил завершающий перевод строки.
