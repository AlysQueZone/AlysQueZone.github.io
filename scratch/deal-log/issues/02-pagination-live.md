# 02: Лог листается и обновляется сам

**What to build:** лог перестаёт быть снимком первой страницы. «Показать ещё» догружает следующую порцию, у конца списка подгрузка идёт сама, а новые сделки приезжают без перезагрузки: наверху — сразу, при прокрутке — плашкой «N новых сделок». Пролистанное не сбрасывается, дубли не появляются.

**Blocked by:** 01 (первый экран и чтение первой страницы).

**Status:** resolved

- [x] «Показать ещё» догружает следующую страницу по курсору; кнопка блокируется на время загрузки; при приближении к концу списка страница подгружается автоматически; кнопка остаётся запасным путём.
- [x] Дубли отсекаются по `id`; дописанные страницы не сдвигают уже показанное; пустая следующая страница не ломает состояние.
- [x] Новые сделки из события `deals` модуля живых данных: если верх лога виден — вставляются сверху; если прокручен — копятся в плашке «N новых сделок»; клик по плашке сливает их и возвращает наверх.
- [x] Статус загрузки и новых сделок объявляется через `role="status"` без навязчивых счётчиков.
- [x] Курсор, слияние и дописывание обобщены так, чтобы работать и для истории лота, и для общего лога; поведение истории лота не изменилось; существующие тесты проходят.
- [x] Новые тесты ядра: одинаковый `created_at` у соседей, пустая свежая страница, дедуп при слиянии, дописывание старой страницы.
- [x] `just check` зелёный.

## Comments

Реализовано: на `/deals/` кнопка «Показать ещё» берёт следующую страницу
`fetchDealLog(DEAL_PAGE_SIZE, historyCursor(shown))`, блокируется на время
запроса; `IntersectionObserver` с запасом 240 px догружает её сам, наблюдатель
пересоздаётся после перерисовки, параллельные загрузки отсекает `loadingMore`.
Дописывание — `appendHistory` (дедуп по `id`, показанное не сдвигается), полная
страница без новых строк и пустой ответ выключают `hasMore`; конец объявляется
через `role="status"`.

Live: подписка на существующее `{ kind: 'deals' }` в `live.subscribe`, свой
канал не открывается. На событие перечитывается только первая страница; если
верх лога не уехал под шапку — новые строки вставляются через `mergeHistory`,
иначе копятся в плашке «N новых сделок» под `--deals-sticky-top`. Клик по
плашке сливает их сверху и возвращает наверх (`prefers-reduced-motion` —
без плавной прокрутки). Пустая/повторная свежая страница ничего не меняет.

Ядро: `historyCursor`/`mergeHistory`/`appendHistory` уже обобщены по
`CursorEntry` (`id` + `created_at`) и работают с `DealEntry`; добавлены тесты на
записях лога — одинаковое время соседей (курсор и дописывание), дедуп при
слиянии, пустая свежая и пустая следующая страница. Поведение истории лота и
её тесты не менялись.

Проверено: `pnpm test` (134 теста), `just check` зелёный. Preview +
`agent-browser` на `/deals/`: первая страница 20 строк, кнопка дала 40,
автоподгрузка при прокрутке дошла до 220 без дублей, `role="status"` сообщает
«Показано N сделок». Live-событие на проде не воспроизводилось — логика
проверена по коду и типам.
