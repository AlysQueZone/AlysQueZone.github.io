# 01: Лог сделок открывается с бегущей строки

**What to build:** чатерс кликает по бегущей строке и попадает на `/deals/`; страница показывает первые 20 сделок биржи, сгруппированные по дням, в раскладке D: липкая полоса дня «пивко», таблица с колонками на десктопе и карточки на телефоне. Миниатюра и название лота ведут на привет. До ответа — скелетон, пусто и ошибка — честные. Это первый сквозной путь: индекс в БД, чтение первой страницы, чистое ядро, страница.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] Вся бегущая строка — ссылка на `/deals/`; у ссылки есть доступное имя, движение замирает на наведении и клавиатурном фокусе; остальные страницы не сломаны.
- [ ] `/deals/` отдаёт первые 20 сделок новыми сверху, сгруппированные по локальным дням; полоса дня — `pivko` + кремовый текст, липнет под шапкой, показывает количество сделок и сумму дня.
- [ ] Десктоп: таблица «Когда / Привет / Продал / Купил / Цена»; мобильный: карточки; миниатюра и название — одна ссылка на страницу привета; на мобильном карточка кликабельна целиком.
- [ ] Состояния: скелетон, «Сделок пока нет — забери первый привет», «Лог не загрузился — проверь связь» с обновлением.
- [ ] Миграция с индексом `purchases_time_idx (created_at DESC, id DESC)`; чтение — keyset-запрос по первой странице; новых колонок, таблиц и грантов нет.
- [ ] Чистое ядро: отбор строк лога (лот, продавец, покупатель, цена, время) и группировка по дням с итогами; тесты на битые строки, «Сегодня/Вчера/дата», границы суток и год.
- [ ] `just check` зелёный; `DESIGN.md` фиксирует `pivko` как фон полосы дня; `GLOSSARY.md` содержит «Лог сделок».
