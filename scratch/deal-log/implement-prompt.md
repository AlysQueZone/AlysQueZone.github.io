Используй skill **`implement-spec`** и реализуй спеку **`scratch/deal-log/spec.md`** по тикетам:

## Что это за фича

Страница **«Лог сделок»** (`/deals/`): вход — вся бегущая строка, вариант **D** — сделки по дням, таблица с колонками, полоса дня **`pivko` + cream**, фильтр «Все / Мои покупки», пагинация, live. Из карточки привета в лог не ходим. Подробности — в спеке.

## Прототип

Локальная ветка **`prototype/deal-log`**, маршрут `/prototype/deals/?variant=D&day=pivko`. Это throwaway: не мержить в реализацию и не переносить код, брать решения и разметку. Ветку не удалять. Если её нет — спека самодостаточна.

## Ограничения

- **Всё локально.** Не открывай PR, не делай `git push`, не запускай `just release`, gh-pages и деплой. Интеграционная ветка — только локальная.
- После зелёной проверки влей локальную интеграционную ветку в локальный `main`; ничего не пушить.
- Не читать и не выводить значения `.env`/`.env.*`. Root-команды — только через askpass.
- Миграции Supabase — файлами; новых таблиц, колонок и грантов нет, только индекс по времени.
- Механику покупки, цены, комиссии, роялти, владения не трогать.
- Не менять `content/` и прод-данные.

## Проверки

- После каждого тикета: `just check` и `pnpm test`.
- Финально: `just preview` + `agent-browser` по `docs/agents/shipping.md`: десктоп и телефон, скелетон, пусто, ошибка, пагинация, live-плашка, «Мои покупки» гостем и с сессией.
- Коммиты — локальные, по тикетам. В конце отчёт: что сделано, какие проверки, что осталось.
