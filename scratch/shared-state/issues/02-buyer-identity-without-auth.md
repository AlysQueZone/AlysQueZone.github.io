# Кто такой покупатель без auth

Type: grilling
Status: resolved
Blocked by: 01, 07

## Question

Как представляем «последнего, кто нажал Купить», если auth нет и не будет: свободный ввод ника чатерса, анонимное «ты», сгенерированный id в localStorage, что-то ещё? Что показываем в карточке лота и истории как `to` (сейчас там строка `'ты'` из `BuyModal.astro`)? Как обрабатываем коллизии ников, смену ника, вандализм и ЛУК (который не продаётся и хозяина не меняет)?

## Answer

Гибрид отвергнут, решение — только Twitch-auth (Supabase Auth Twitch-провайдер, см. тикет про Twitch-auth): гостей нет, покупает только залогиненный. Identity = стабильный Twitch user id (цифры, `sub`); показ — login-снапшот на момент покупки, старые записи при смене ника не переписываем; коллизии невозможны по построению. Точка входа: «Купить» без сессии уводит в логин Twitch с возвратом к тому же лоту и переоткрытием модалки. Сессия долгая (persist + авторефреш supabase-js, вход один раз). Витрина и карточки открыты всем (шаринг в чат не ломаем), закрыта только покупка; нет сессии/офлайн — честная ошибка + запрет покупки (согласуется со scope-решением fail-closed). RLS-упрощение: пишет только `TO authenticated`, anon-записи нет. Решено граллингом 2026-09-06, все ответы — рекомендованные.
