# Пивкойны за Баллы канала Twitch (Channel Points): теоретический контур обмена

Дата: 2026-09-08

## Постановка вопроса

Как выдавать Пивкойны (внутренняя шуточная валюта сайта AlysQueZone) за Баллы канала Twitch (Channel Points)? Сейчас бэкенда под это нет. Нужен теоретический пошаговый пример: как это сделать и использовать. Терминология — из `CONTEXT.md`: Чатерс — зритель чата, Стример — ведущая канала, Пивкойн — валюта биржи (старт 1000), Баллы канала — очки лояльности Twitch, не путать с Пивкойном. Канал: https://www.twitch.tv/alysque, ID `224473232`.

## Краткий ответ-вердикт

- Баллы канала тратятся Чатерсом на **Custom Reward** Стримера (например «Обменять 500 баллов на 100 пивкойнов»); факт траты называется **redemption**. Награды создаёт и ими управляет канал Стримера — через дашборд или Helix API ([Create Custom Rewards](https://dev.twitch.tv/docs/api/reference/#create-custom-rewards)).
- Все операции с наградами и обменами требуют **токен самого Стримера** (user access token, `broadcaster_id` обязан совпадать с user ID в токене) и скопы `channel:manage:redemptions` (запись) / `channel:read:redemptions` (чтение) ([scopes](https://dev.twitch.tv/docs/authentication/scopes/)).
- Узнать о факте обмена в реальном времени можно только через **EventSub**: `channel.channel_points_custom_reward_redemption.add` (факт) и `.update` (смена статуса), транспорты — webhook, websocket, conduit ([EventSub overview](https://dev.twitch.tv/docs/eventsub/), [subscription types](https://dev.twitch.tv/docs/eventsub/eventsub-subscription-types/#channelchannel_points_custom_reward_redemptionadd)).
- **Чистой статикой в браузере это сделать нельзя** — секрет приложения и токен Стримера запрещено светить в клиентском JS ([Register Your App](https://dev.twitch.tv/docs/authentication/register-app/)), а токен каждого Чатерса не имеет прав на чужие обмены.
- Минимальный рабочий контур без своего сервера: **Supabase Edge Function как webhook-callback** (публичный HTTPS на 443-м порту) → проверка HMAC-подписи → начисление Пивкойнов в Postgres → `FULFILLED` через Helix ([Handling Webhook Events](https://dev.twitch.tv/docs/eventsub/handling-webhook-events/), [Edge Functions invoke](https://github.com/supabase/supabase/blob/master/apps/docs/content/guides/functions/deploy.mdx)).
- Жёсткие ограничения: Баллы канала доступны только каналам **партнёров/аффилиатов** (иначе API отвечает 400) ([Helix reference](https://dev.twitch.tv/docs/api/reference/#create-custom-rewards)); обмен можно выполнить только в статусе `UNFULFILLED` и только приложением, создавшим награду ([Update Redemption Status](https://dev.twitch.tv/docs/api/reference/#update-redemption-status)); уведомления EventSub — at-least-once, поэтому начисление обязано быть **идемпотентным** по ID обмена ([EventSub overview](https://dev.twitch.tv/docs/eventsub/)).
- Для AlysQueZone это означает: обмен «баллы → пивкойны» требует появления серверной стороны (Edge Function + секреты Стримера в Supabase), то есть выхода за рамки «только статика». Без этого реален лишь ручной обмен (Стример/модератор начисляет вручную через дашборд).

## Полный разбор

### 1. Что такое Channel Points, Custom Rewards и redemption

- **Channel Points (Баллы канала)** — очки лояльности, которые Чатерсы копят просмотром и тратят на награды канала. Это деньги Twitch, а не сайта: напрямую «перевести» их в Пивкойны нельзя, можно лишь отследить факт траты и начислить Пивкойны со своей стороны.
- **Custom Reward** — пользовательская награда, которую создаёт канал Стримера (через дашборд креатора или Helix `POST /helix/channel_points/custom_rewards`). Лимит — максимум 50 наград на канал, включая отключённые ([Create Custom Rewards](https://dev.twitch.tv/docs/api/reference/#create-custom-rewards)). У награды есть название (до 45 символов, уникальное), цена в баллах (`cost`, минимум 1), опциональный `prompt`, лимиты на стрим/пользователя/кулдаун и флаг `should_redemptions_skip_request_queue` ([Create Custom Rewards](https://dev.twitch.tv/docs/api/reference/#create-custom-rewards)).
- **Redemption (redeem)** — факт того, что Чатерс потратил баллы на награду. У обмена есть жизненный цикл статусов: `UNFULFILLED` (ожидает исполнения) → `FULFILLED` (исполнено) либо `CANCELED` (отменено, баллы возвращаются зрителю). Перевести обмен в `FULFILLED`/`CANCELED` можно только пока он в `UNFULFILLED`, и только приложением, которое создало награду; установка `CANCELED` возвращает баллы пользователю ([Update Redemption Status](https://dev.twitch.tv/docs/api/reference/#update-redemption-status)). Если при создании награды выставлен `should_redemptions_skip_request_queue: true`, обмены сразу становятся `FULFILLED` без очереди — для нашего кейса нужен `false`, чтобы начисление Пивкойнов происходило до подтверждения ([Create Custom Rewards](https://dev.twitch.tv/docs/api/reference/#create-custom-rewards)).

### 2. Helix endpoints, скопы, чей токен

Все URL ниже — `https://api.twitch.tv/helix/...`, во всех запросах заголовки `Authorization: Bearer <user-token>` + `Client-Id: <client-id>` (примеры — в референсе каждого эндпоинта, [Twitch API Reference](https://dev.twitch.tv/docs/api/reference/)).

| Операция                   | Endpoint                                                                                                                                              | Скоп                                                        |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| Создать награду            | `POST /channel_points/custom_rewards?broadcaster_id=...`                                                                                              | `channel:manage:redemptions`                                |
| Список наград              | `GET /channel_points/custom_rewards?broadcaster_id=...`                                                                                               | `channel:read:redemptions` или `channel:manage:redemptions` |
| Список обменов награды     | `GET /channel_points/custom_rewards/redemptions?broadcaster_id=...&reward_id=...&status=UNFULFILLED`                                                  | `channel:read:redemptions` или `channel:manage:redemptions` |
| Подтвердить/отменить обмен | `PATCH /channel_points/custom_rewards/redemptions?id=...&broadcaster_id=...&reward_id=...`, body `{"status":"FULFILLED"}` или `{"status":"CANCELED"}` | `channel:manage:redemptions`                                |
| Изменить/удалить награду   | `PATCH` / `DELETE /channel_points/custom_rewards?broadcaster_id=...&id=...`                                                                           | `channel:manage:redemptions`                                |

Соответствие скопов эндпоинтам зафиксировано в таблице скопов ([Scopes: channel:read:redemptions, channel:manage:redemptions](https://dev.twitch.tv/docs/authentication/scopes/)), требования каждого эндпоинта — в его секции референса ([Create Custom Rewards](https://dev.twitch.tv/docs/api/reference/#create-custom-rewards), [Get Custom Reward Redemption](https://dev.twitch.tv/docs/api/reference/#get-custom-reward-redemption), [Update Redemption Status](https://dev.twitch.tv/docs/api/reference/#update-redemption-status)).

Ключевое: **токен нужен Стримера, не Чатерса**. У всех записывающих и читающих эндпоинтов `broadcaster_id` обязан совпадать с user ID в OAuth-токене, а получить список обменов может только приложение, создавшее награду ([Create Custom Rewards](https://dev.twitch.tv/docs/api/reference/#create-custom-rewards), [Get Custom Reward Redemption](https://dev.twitch.tv/docs/api/reference/#get-custom-reward-redemption), [Update Redemption Status](https://dev.twitch.tv/docs/api/reference/#update-redemption-status)). Токен Чатерса здесь бесполезен: он не даёт прав исполнять чужие обмены на канале Стримера.

### 3. EventSub: как узнать о redeem без своего сервера

EventSub — штатный способ получать события Twitch почти в реальном времени; подписки транспорт-независимы, но транспорт выбирать нужно ([EventSub overview](https://dev.twitch.tv/docs/eventsub/)). Для кейса нужны два типа подписок ([Subscription Types](https://dev.twitch.tv/docs/eventsub/eventsub-subscription-types/#channelchannel_points_custom_reward_redemptionadd)):

- `channel.channel_points_custom_reward_redemption.add` v1 — «Чатерс обменял награду». Требует скоп `channel:read:redemptions` или `channel:manage:redemptions`; в `condition` — `broadcaster_user_id`, опционально `reward_id` для фильтра на одну награду; стоимость подписки 0. В событии приходят `id` обмена, `user_id`/`user_login` Чатерса, `status: "unfulfilled"`, объект `reward` (id/title/cost) и `redeemed_at`.
- `channel.channel_points_custom_reward_redemption.update` v1 — «статус обмена изменился» (те же скопы и condition). Полезна как страховка/аудит, основной триггер начисления — `.add`.

Три транспорта и их пригодность при условии «нет своего сервера, только статика + Supabase Free»:

- **Webhook** — единственный реалистичный вариант. Нужен публичный HTTPS-callback на порту 443 ([Handling Webhook Events](https://dev.twitch.tv/docs/eventsub/handling-webhook-events/)); URL Supabase Edge Function (`https://<project>.supabase.co/functions/v1/<name>`, [quickstart-dashboard](https://github.com/supabase/supabase/blob/master/apps/docs/content/guides/functions/quickstart-dashboard.mdx)) этому требованию удовлетворяет. Подписка создаётся с **app access token**, но для скоповых типов пользователь (Стример) должен заранее выдать приложению нужные скопы через user-токен на том же client ID ([Managing Subscriptions: Authorization](https://dev.twitch.tv/docs/eventsub/manage-subscriptions/)). При подписке Twitch шлёт challenge (`webhook_callback_verification`), на который функция обязана ответить 200 с raw-строкой challenge ([Handling Webhook Events: challenge](https://dev.twitch.tv/docs/eventsub/handling-webhook-events/)). Каждое уведомление подписывается HMAC-SHA256 на секрете 10–100 символов (конкатенация `Message-Id + Message-Timestamp + raw body`), проверять обязательно до любой обработки ([Handling Webhook Events: verifying](https://dev.twitch.tv/docs/eventsub/handling-webhook-events/)).
- **WebSocket** (`wss://eventsub.wss.twitch.tv/ws`) — не подходит: требует постоянно живое соединение, подписка — только с **user access token** ([Managing Subscriptions: Authorization](https://dev.twitch.tv/docs/eventsub/manage-subscriptions/), [Handling WebSocket Events](https://dev.twitch.tv/docs/eventsub/handling-websocket-events/)), на подписку после welcome даётся 10 секунд, при обрыве соединения нужно переподписываться, а **потерянные за время обрыва события не переигрываются** ([Handling WebSocket Events](https://dev.twitch.tv/docs/eventsub/handling-websocket-events/)). Держать такое соединение может только всегда включённый процесс — браузерная вкладка им не является. Лимиты — до 3 соединений и 300 подписок на соединение ([Handling WebSocket Events: limits](https://dev.twitch.tv/docs/eventsub/handling-websocket-events/)).
- **Conduit** — обёртка для балансировки между шардами, прямо названа транспортом «для backend-приложений», требует app access token ([Handling Conduit Events](https://dev.twitch.tv/docs/eventsub/handling-conduit-events/)). Для одного канала и одной награды — избыточна.

Вывод по транспортам: webhook на Edge Function — да; websocket из браузеров Чатерсов — нет; conduit — не нужен.

### 4. Почему нельзя обойтись только статикой в браузере (честный вердикт: нет)

1. **Секрет приложения нельзя класть в клиент.** Дока прямо требует хранить client secret как пароль и никогда не показывать пользователям даже в скрытом виде ([Register Your App](https://dev.twitch.tv/docs/authentication/register-app/)). Любой обмен кода на токен (`authorization_code` flow) требует секрета ([Getting OAuth Tokens](https://dev.twitch.tv/docs/authentication/getting-tokens-oauth/)), значит делать его из браузера нельзя. Поток без сервера (implicit grant) существует именно для клиентских приложений ([Getting OAuth Tokens](https://dev.twitch.tv/docs/authentication/getting-tokens-oauth/)), но он выдаёт токен текущего пользователя — то есть Чатерса, а не Стримера.
2. **Нужен именно токен Стримера со скопом `channel:manage:redemptions`.** Положить токен Стримера в JS статике = отдать любому открывшему исходники право создавать/удалять награды и подтверждать/отменять чужие обмены на канале. Это не «риск», это гарантированная компрометация.
3. **Fulfillment обязан делать доверенный исполнитель.** Подтвердить обмен может только приложение-создатель награды и только из `UNFULFILLED` ([Update Redemption Status](https://dev.twitch.tv/docs/api/reference/#update-redemption-status)). Если начисление Пивкойнов делает браузер Чатерса, он же решает, когда слать `FULFILLED`: ничто не мешает подделать начисление себе и подтвердить обмен.
4. **Надёжность недостижима из вкладки.** Webhook принимать негде (нужен входящий HTTPS), websocket-соединение умирает с закрытием вкладки, а пропущенные события Twitch не переигрывает ([Handling WebSocket Events](https://dev.twitch.tv/docs/eventsub/handling-websocket-events/)). Обмены, сделанные пока сайт закрыт, были бы потеряны.
5. Опрос `GET redemptions` из браузера упирается в то же самое: нужен токен Стримера, светить который нельзя ([Get Custom Reward Redemption](https://dev.twitch.tv/docs/api/reference/#get-custom-reward-redemption)).

### 5. Теоретический минимальный контур с Supabase (предпочтительный бэкенд проекта)

Цепочка: награда «Обменять баллы на N пивкойнов» → EventSub webhook на Edge Function (проверка подписи секретом) → начисление в Postgres → `FULFILLED` через Helix. Теория, без миграций.

- **Edge Function** (Deno, `Deno.serve`, секреты через `Deno.env`/`supabase secrets set`, вызов по публичному HTTPS-URL — паттерны из [Supabase docs](https://github.com/supabase/supabase/blob/master/apps/docs/content/guides/functions/deploy.mdx) и [quickstart](https://github.com/supabase/supabase/blob/master/apps/docs/content/guides/functions/quickstart-dashboard.mdx)). Обязанности: ответить на challenge 200 с raw-телом ([Handling Webhook Events: challenge](https://dev.twitch.tv/docs/eventsub/handling-webhook-events/)); проверить HMAC-SHA256 подпись до обработки ([Handling Webhook Events: verifying](https://dev.twitch.tv/docs/eventsub/handling-webhook-events/)); ответить 2xx быстро (долгая обработка — после ответа, иначе подписку отзовут со статусом `notification_failures_exceeded`, [Handling Webhook Events](https://dev.twitch.tv/docs/eventsub/handling-webhook-events/)); отбросить повторы по `Twitch-Eventsub-Message-Id`/ID обмена — уведомления шлются at-least-once ([EventSub overview](https://dev.twitch.tv/docs/eventsub/)).
- **Таблица `balances` (теория):** `twitch_id text primary key` (стабильный identity — тот же `user_id`, что приходит в событии EventSub и уже используется как identity покупателя в shared-state), `login text` (снапшот ника, не переписывать историю), `balance bigint`, `updated_at timestamptz`.
- **Таблица `point_exchanges` (теория, журнал идемпотентности):** `redemption_id text primary key` (ID обмена из события — естественный ключ дедупликации), `user_id`, `user_login`, `reward_id`, `points_spent int`, `pivkoiny_credited bigint`, `status text` (`credited`/`refunded`), `created_at`. Порядок операций: `INSERT redemption` → при конфликте по PK пропустить (повтор) → `UPDATE balances` → `PATCH FULFILLED`; при сбое — `PATCH CANCELED` (возврат баллов, [Update Redemption Status](https://dev.twitch.tv/docs/api/reference/#update-redemption-status)).
- **Политики (теория):** RLS включён; клиентам (`anon`/`authenticated`) — только `SELECT` балансов; `INSERT`/`UPDATE` — только через `service_role`, которым владеет Edge Function. Клиентский JS видит витрину балансов, но начислить себе ничего не может — та же модель, что уже принята для покупок в shared-state (клиент только читает/просит, считает доверенная сторона).
- Курс обмена (например 500 баллов → 100 пивкойнов) задаётся ценой награды (`cost`) и фиксированным множителем в функции; антифарм-рычаги — штатные поля награды: `max_per_user_per_stream`, `max_per_stream`, `global_cooldown_seconds` ([Create Custom Rewards](https://dev.twitch.tv/docs/api/reference/#create-custom-rewards)).

### 6. Ограничения и подводные камни

- **Affiliate/Partner обязателен.** Все Channel Points эндпоинты отвечают 400 «broadcaster is not a partner or affiliate» для обычных каналов ([Create Custom Rewards](https://dev.twitch.tv/docs/api/reference/#create-custom-rewards), аналогичные ошибки у [Get/Update](https://dev.twitch.tv/docs/api/reference/#update-redemption-status)). Перед работой проверить статус канала alysque.
- **Задержка и повторы EventSub.** Уведомления — at-least-once с ретраями; дедуп по ID сообщения/обмена обязателен ([EventSub overview](https://dev.twitch.tv/docs/eventsub/), заголовок `Twitch-Eventsub-Message-Retry`, [Handling Webhook Events](https://dev.twitch.tv/docs/eventsub/handling-webhook-events/)). Для защиты от реплеев сверять `message_timestamp` (не старше ~10 минут) — рекомендация [EventSub overview](https://dev.twitch.tv/docs/eventsub/).
- **Кто может подтвердить обмен.** Только `UNFULFILLED` → `FULFILLED`/`CANCELED` и только приложением-создателем награды; исполненные/отменённые обмены видны через API лишь несколько дней ([Update Redemption Status](https://dev.twitch.tv/docs/api/reference/#update-redemption-status), [Get Custom Reward Redemption](https://dev.twitch.tv/docs/api/reference/#get-custom-reward-redemption)). Потеря client_id/секретов создавшего приложения = потеря управления наградой (удалить и пересоздать может только оно).
- **Токены живут недолго и протухают.** User-токены имеют `expires_in` (часы) и обновляются через refresh token из Authorization Code flow; app-токены не обновляются ([Refreshing Access Tokens](https://dev.twitch.tv/docs/authentication/refresh-tokens/)). Реакция на 401 — обновить токен и повторить; refresh может инвалидироваться (смена пароля, отзыв доступа) — тогда нужно заново прогнать consent ([Refreshing Access Tokens](https://dev.twitch.tv/docs/authentication/refresh-tokens/)).
- **Лимиты Twitch API.** Token-bucket на client ID, при превышении — 429; следить по заголовкам `Ratelimit-Limit/Remaining/Reset` ([Twitch API Concepts: Rate Limits](https://dev.twitch.tv/docs/api/guide/)). Наш контур лёгкий (1 PATCH на обмен + ретраи), но функцию-исполнитель не дёргать в цикле.
- **Злоупотребления.** Баллы копятся просмотром, фармятся idle-зрителями; обмен без лимитов напечатает Пивкойны и обесценит биржу. Лечится ценой награды, `max_per_user_per_stream`, кулдаунами ([Create Custom Rewards](https://dev.twitch.tv/docs/api/reference/#create-custom-rewards)) и консервативным курсом.
- **Отладка без стрима.** Тестировать webhook-хендлер можно Twitch CLI (`twitch event verify-subscription`, `twitch event trigger`) без SSL ([Handling Webhook Events: CLI](https://dev.twitch.tv/docs/eventsub/handling-webhook-events/), [Twitch CLI](https://dev.twitch.tv/docs/cli/)); CLI ставится через brew/scoop или релизами с GitHub ([Twitch CLI install](https://dev.twitch.tv/docs/cli/)).
- **Supabase Free.** Edge Function живёт на том же домене проекта, секреты — в окружении функции, не в репо. Актуальные лимиты free-tier (инвокации, время выполнения, сон после простоя) сверять с pricing/доками перед продом; холодный старт учитывать в требовании «ответить 2xx за секунды» ([Handling Webhook Events](https://dev.twitch.tv/docs/eventsub/handling-webhook-events/), [invoke via URL](https://github.com/supabase/supabase/blob/master/apps/docs/content/guides/functions/deploy.mdx)).

## Пошаговый теоретический пример (владелец канала alysque, ID 224473232)

Всё ниже — теория для ручного прогона человеком; секреты — только в локальном терминале/настройках Supabase, никогда в репо и браузер.

**Шаг 0. Предусловия.** Канал — affiliate/partner (иначе 400, [Create Custom Rewards](https://dev.twitch.tv/docs/api/reference/#create-custom-rewards)). Учётка Стримера с включённой 2FA (путь для +7 — через не-RU SIM + TOTP, детали уже зафиксированы в shared-state). Supabase-проект уже есть (используется shared-state).

**Шаг 1. Зарегистрировать приложение в dev.twitch.tv/console.** Войти под Стримером → Applications → Register Your Application: имя (уникальное), OAuth Redirect URL (например адрес Edge Function или локалка для разового прогона), категория; забрать Client ID, сгенерировать Client Secret и сохранить локально. Секрет — как пароль, пользователям не показывать ([Register Your App](https://dev.twitch.tv/docs/authentication/register-app/)).

**Шаг 2. Получить токен Стримера (Authorization Code flow).** В браузере Стримера открыть (склеить в одну строку, подставить client_id и redirect):
`https://id.twitch.tv/oauth2/authorize?response_type=code&client_id=<CLIENT_ID>&redirect_uri=<REDIRECT>&scope=channel%3Amanage%3Aredemptions+channel%3Aread%3Aredemptions&state=<random>` — параметры и формат ответа (`?code=...&scope=...&state=...`) по [Getting OAuth Tokens](https://dev.twitch.tv/docs/authentication/getting-tokens-oauth/). Затем обменять код на токены **серверной стороной/локальным curl, не в браузере** (нужен секрет):
`curl -X POST 'https://id.twitch.tv/oauth2/token' -H 'Content-Type: application/x-www-form-urlencoded' -d 'client_id=<ID>&client_secret=<SECRET>&code=<CODE>&grant_type=authorization_code&redirect_uri=<REDIRECT>'` — ответ содержит `access_token` + `refresh_token` ([Getting OAuth Tokens](https://dev.twitch.tv/docs/authentication/getting-tokens-oauth/)). Access token сохранить в секреты Supabase, refresh — в надёжное локальное хранение для обновления ([Refreshing Access Tokens](https://dev.twitch.tv/docs/authentication/refresh-tokens/)).

**Шаг 3. Создать награду «Баллы → Пивкойны».** Можно в дашборде креатора, а через API (токен Стримера):
`curl -X POST 'https://api.twitch.tv/helix/channel_points/custom_rewards?broadcaster_id=224473232' -H 'Authorization: Bearer <STREAMER_TOKEN>' -H 'Client-Id: <CLIENT_ID>' -H 'Content-Type: application/json' -d '{"title":"100 пивкойнов за баллы","cost":500,"prompt":"Пивкойны упадут на твой баланс на сайте биржи","is_enabled":true,"is_max_per_user_per_stream_enabled":true,"max_per_user_per_stream":2,"is_global_cooldown_enabled":true,"global_cooldown_seconds":300,"should_redemptions_skip_request_queue":false}'` — поля и лимиты по [Create Custom Rewards](https://dev.twitch.tv/docs/api/reference/#create-custom-rewards/). Записать `id` награды (`reward_id`). Важно: исполнять обмены сможет только это приложение ([Update Redemption Status](https://dev.twitch.tv/docs/api/reference/#update-redemption-status)).

**Шаг 4. Поднять Edge Function-приёмник.** Функция с публичным URL `https://<project>.supabase.co/functions/v1/twitch-redeem` ([Function URL pattern](https://github.com/supabase/supabase/blob/master/apps/docs/content/guides/functions/quickstart-dashboard.mdx)): отвечает на challenge raw-строкой с 200 ([Handling Webhook Events: challenge](https://dev.twitch.tv/docs/eventsub/handling-webhook-events/)), проверяет HMAC-SHA256 по секрету подписки ([Handling Webhook Events: verifying](https://dev.twitch.tv/docs/eventsub/handling-webhook-events/)), быстро отвечает 2xx и только потом работает ([Handling Webhook Events](https://dev.twitch.tv/docs/eventsub/handling-webhook-events/)). Секрет подписки (10–100 ASCII-символов) сгенерировать локально и положить в секреты функции ([Handling Webhook Events: verifying](https://dev.twitch.tv/docs/eventsub/handling-webhook-events/), [Supabase secrets](https://github.com/supabase/supabase/blob/master/examples/prompts/edge-functions.md)).

**Шаг 5. Подписаться на событие обмена.** Нужен **app access token** того же client ID (client credentials flow: `grant_type=client_credentials`, [Getting OAuth Tokens](https://dev.twitch.tv/docs/authentication/getting-tokens-oauth/)); скопы уже выданы Стримером на шаге 2 ([Managing Subscriptions: Authorization](https://dev.twitch.tv/docs/eventsub/manage-subscriptions/)):
`curl -X POST 'https://api.twitch.tv/helix/eventsub/subscriptions' -H 'Authorization: Bearer <APP_TOKEN>' -H 'Client-Id: <CLIENT_ID>' -H 'Content-Type: application/json' -d '{"type":"channel.channel_points_custom_reward_redemption.add","version":"1","condition":{"broadcaster_user_id":"224473232","reward_id":"<REWARD_ID>"},"transport":{"method":"webhook","callback":"https://<project>.supabase.co/functions/v1/twitch-redeem","secret":"<SUB_SECRET>"}}'` — формат запроса/ответа (`webhook_callback_verification_pending` → `enabled`) по [Managing Subscriptions](https://dev.twitch.tv/docs/eventsub/manage-subscriptions/), пример тела для этого типа — в [Subscription Types](https://dev.twitch.tv/docs/eventsub/eventsub-subscription-types/#channelchannel_points_custom_reward_redemptionadd).

**Шаг 6. Обработка redeem.** Чатерс тратит 500 баллов в чате → Twitch шлёт на функцию событие со `status: "unfulfilled"`, `user_id`, `reward.cost` ([Subscription Types payload](https://dev.twitch.tv/docs/eventsub/eventsub-subscription-types/#channelchannel_points_custom_reward_redemptionadd)). Функция: проверить подпись и свежесть ([Handling Webhook Events](https://dev.twitch.tv/docs/eventsub/handling-webhook-events/), [EventSub overview](https://dev.twitch.tv/docs/eventsub/)) → `INSERT` в `point_exchanges` по `redemption_id`, при конфликте — стоп (дубль) → `UPDATE balances` (`twitch_id = user_id`, +100) → подтвердить обмен токеном Стримера:
`curl -X PATCH 'https://api.twitch.tv/helix/channel_points/custom_rewards/redemptions?id=<REDEMPTION_ID>&broadcaster_id=224473232&reward_id=<REWARD_ID>' -H 'Authorization: Bearer <STREAMER_TOKEN>' -H 'Client-Id: <CLIENT_ID>' -H 'Content-Type: application/json' -d '{"status":"FULFILLED"}'` ([Update Redemption Status](https://dev.twitch.tv/docs/api/reference/#update-redemption-status)). Если начисление не удалось — тот же запрос с `{"status":"CANCELED"}` (баллы вернутся Чатерсу, [Update Redemption Status](https://dev.twitch.tv/docs/api/reference/#update-redemption-status)).

**Шаг 7. Эксплуатация.** При 401 от Helix — обновить access token через refresh (`grant_type=refresh_token`, [Refreshing Access Tokens](https://dev.twitch.tv/docs/authentication/refresh-tokens/)) и сохранить новый refresh (он может меняться). Подписки не протухают сами, но отзываются при смене пароля/отзыве доступа/`notification_failures_exceeded`/удалении типа ([Handling Webhook Events: revocation](https://dev.twitch.tv/docs/eventsub/handling-webhook-events/)) — мониторить `GET /helix/eventsub/subscriptions` ([Managing Subscriptions](https://dev.twitch.tv/docs/eventsub/manage-subscriptions/)). Курс/цену менять через `PATCH` награды ([Update Custom Reward](https://dev.twitch.tv/docs/api/reference/#update-custom-reward)); локальный баланс Пивкойнов сайта при этом остаётся косметикой до момента, когда `balances` станет общей.

## Что это значит для AlysQueZone без бэкенда

- Сегодня проект — «только статика + Supabase как shared-хранилище с клиентскими INSERT», а Пивкойны — локальная косметика (зафиксировано в shared-state spec). Обмен «баллы → пивкойны» в эту модель **не ложится**: нужен доверенный исполнитель с секретами Стримера, а его в браузере быть не может ([Register Your App](https://dev.twitch.tv/docs/authentication/register-app/), раздел 4 выше).
- Ближайший допустимый шаг в рамках конвенций проекта — Supabase Edge Function: своего сервера по-прежнему нет, бюджет 0₽, домен тот же (открытие из РФ уже проверено для Supabase в этом усилии). Это расширение бэкенд-поверхности (секреты, service_role в функции, мониторинг подписок), поэтому решение — за человеком.
- Дешёвая альтернатива без кода: **ручной обмен** — Чатерс тратит баллы на награду-заглушку («показать ник для ручного начисления»), Стример/модератор раз в стрим сверяет очередь обменов в дашборде креатора и правит балансы через Supabase Dashboard. Работает на существующих правах, но не автоматизировано и требует дисциплины.
- Связка identity бесплатная: событие EventSub уже несёт `user_id`/`user_login` Чатерса ([Subscription Types](https://dev.twitch.tv/docs/eventsub/eventsub-subscription-types/#channelchannel_points_custom_reward_redemptionadd)) — тот же стабильный `twitch_id`, что принят как identity покупателя в shared-state. Отдельный OAuth для Чатерсов под обмен не нужен.
- Рекомендация: не трогать экономику до решения человека; если зелёный свет — первым делом проверить affiliate-статус канала (иначе всё выше неприменимо, [Create Custom Rewards](https://dev.twitch.tv/docs/api/reference/#create-custom-rewards)), затем прогнать шаги 1–6 на тестовой награде с `cost: 1` и `max_per_user_per_stream: 1`.
