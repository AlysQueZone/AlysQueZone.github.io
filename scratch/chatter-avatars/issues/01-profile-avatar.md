# 01: Аватар в паспорте профиля

**What to build:** у счёта с аватаром Twitch паспорт профиля показывает картинку вместо инициалов; без аватара или при ошибке загрузки — прежние инициалы. Источник — метаданные Supabase Auth, публичный read model отдаёт URL, storage и загрузка не появляются.

**Blocked by:** None (профиль и `public_profile` уже в `main`-линии `feature/chatter-profile`).

**Status:** ready-for-agent

- [ ] `profiles.avatar_url text` + бэкфилл из `auth.users.raw_user_meta_data` (`avatar_url` → `picture`); тот же триггер, что синкает логин, обновляет картинку при вставке и изменении метаданных, пустые метаданные не затирают старую.
- [ ] `public_profile(uid)` возвращает `avatar_url`; новых грантов/политик нет, колонка `profiles` клиентам не открывается.
- [ ] Чистое ядро: `ProfileStats.avatarUrl` только `https:` или `null`; тесты на валидный URL, отсутствие, пустую строку, `http:`, мусор и `javascript:`.
- [ ] Паспорт: `<img>` в том же квадрате 64×64, `alt=""`, `width`/`height`, `loading="lazy"`, `decoding="async"`, `referrerpolicy="no-referrer"`; инициалы — фолбэк при отсутствии URL и при `error` картинки, без скачка высоты.
- [ ] Комментарии и документы: `docs/adr/0014-public-chatter-profile.md` больше не говорит «без аватаров»; шапка модуля профиля описывает фолбэк; `AGENTS.md` — указатель на источник аватара.
- [ ] Гейты `just check` зелёные; `pnpm build` не ходит в БД.
- [ ] Проверено на локальном Supabase и в preview: гость/свой/чужой профиль, аватар есть/нет/битый URL, телефон и десктоп.
