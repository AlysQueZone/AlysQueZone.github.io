# 02: Колокольчик — первая продажа автора в оффлайн-догоне и без старых повторов

**What to build:** Чатерс, у которого перекупили лот при закрытой вкладке, видит эту сделку в панели «Перекупы твоих лотов», когда возвращается. Это работает и для автора привета на первой продаже его лота — сейчас такая сделка в догон не попадает, и дыра задокументирована комментарием в коде. Сделки, которые чатерс уже видел, перестают всплывать в панели при каждой загрузке страницы.

Спека: `scratch/purchase-seller/spec.md`.

**Blocked by:** 01 (нужны продавец в схеме и чистый модуль чтения сделок)

**Status:** ready-for-agent

- [ ] Оффлайн-догон берёт продавца из БД (сделки, где продавец — я), а не восстанавливает цепочку покупок: первая продажа лота из заявки доходит до автора.
- [ ] Сделки, которые чатерс уже видел, в панель не возвращаются: догон ограничен меткой просмотра, если она есть; непрочитанное считается как раньше.
- [ ] Лот, которым я владею сейчас (выкупленный обратно), в догон не попадает, как и раньше.
- [ ] Потолок в 500 строк, который при сортировке по возрастанию мог отрезать свежие события, уходит вместе с реконструкцией цепочки: свежие события первыми, лимит по числу событий.
- [ ] Чистый модуль чтения сделок получает второй метод — строки в события перекупа — и тесты ядра: только мои продажи, свежие первыми, уважение лимита, выкупленный обратно лот исключён.
- [ ] Комментарий, документирующий дыру («первая продажа владельца-не-покупателя не покрывается»), снят.
- [ ] `CHANGELOG.md`: своя строка про колокольчик.
- [ ] `just check` зелёный, `npm run build` собирается.
- [ ] После выката проверено на живых данных: у чатерса с историей продаж панель после перезагрузки страницы не наполняется старыми сделками, а первая продажа лота из заявки доходит до автора.
