## 1. RLS-матрица — ЗЕЛЁНАЯ (42 проверки)

Метод: throwaway-Postgres 18 в docker (контейнер после прогона удалён) + стабы
`auth.uid()/auth.jwt()` через `request.jwt.claim.sub/claims` + минимальные `lots/purchases`
в форме базовой миграции (с её грантами `select` и триггерами покупки — тикет 08
только *заменяет* функции, триггеры `trg_purchases_*` живут в базе).
Все 5 пивкойн-миграций встали `ON_ERROR_STOP=1` без ошибок, по порядку спеки:
`profiles → ledger → gamba_spins/RPC → daily_claims/RPC → lots_with_next_price`.

Матрица (роли `anon` / `authenticated`-A / `authenticated`-B, свой/чужой):
- `profiles`: A видит только свой ряд (1000), insert/update/delete клиентом запрещены;
  B чужого не видит; anon — denied (гранта нет, так задумано).
- `ledger`: то же самое (1 seed-ряд у A, записи запрещены).
- `gamba_spins`: пусто, прямая вставка запрещена (только RPC).
- `gamba_payouts`: читают все (anon+A = 3 ряда), вставка запрещена.
- `daily_claims`: пусто, прямая вставка запрещена (только RPC).
- `lots_with_next_price`: anon читает (>=1 ряд).
- RPC `spin_gamba`: исход возвращается, `balance = 900 + payout`; повтор с тем же
  ключом — тот же исход/баланс, дублей нет (`spins = 2` после двух разных ключей).
- RPC `claim_daily`: первый клейм `100/streak 1/already=false`, повтор —
  `already=true`, баланс не меняется, дублей нет (`claims = 1`).
- Деньги покупки 08: `price_paid = ceil(100*1.1) = 110`, покупатель списан ровно
  на `price_paid`, продавец получил `1000+110`, в леджере `purchase_debit+credit`.
- `insufficient funds`: Чатерс C, честно слитый китовым лотом до 10, получает отказ
  спина (`insufficient funds: need 100, have 10`).
- Инвариант «баланс = сумма движений» — 0 нарушителей по всем счетам.

Итог: **40 PASS в матрице + 2 проверки идемпотентности, 0 FAIL**.
Скрипты жили только в `/tmp/opencode` (в репо не коммитятся).

Нюансы для будущих тестов (не дефекты): антибот-лимит гамбы (1 спин/2с) требует
пауз между спинами одного юзера в тестах, т.к. внутри одной транзакции `now()`
заморожен — спины гонять отдельными транзакциями.

Дефектов в коде миграций/клиента не найдено → кодовых правок нет.

## 2. RTP таблицы A — 90% ПОДТВЕРЖДЕНО исполнением

Конфиг БД: `miss 50%→0, return 40%→100, jackpot 10%→500`, ставка 100.
- Полный перебор (PAR, не аппроксимация): `EV = 0.5*0 + 0.4*100 + 0.1*500 = 90.0` → **RTP 90.00%**.
- Монте-Карло (seed 1207): N=1k → 89.90%, 10k → 88.57%, 100k → 89.53%, 1M → 89.99% — сходится к 90%.

## 3. Database Advisors (MCP supabase, живой прод)

- Performance: чисто, замечаний нет.
- Security: 3 WARN, все **вне scope пивкойнов** (предсуществующие): `rls_auto_enable()`
  исполняема anon+authenticated, выключена leaked-password-protection. Наших функций

  `search_path`) линтер не флагнул. Действий по ним в этом тикете нет.
