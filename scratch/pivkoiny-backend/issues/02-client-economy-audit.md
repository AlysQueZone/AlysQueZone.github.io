## Question

Что именно в клиенте сегодня трогает экономику и должно переехать на бэк? Без решений — только инвентаризация, чтобы следующие тикеты решали на фактах.

Пройти: `src/lib/wallet.ts` (getBalance/canAfford/spend/earn, START_BALANCE), `src/components/GambaModal.astro` (взвешенный исход, earn на выигрыше), `src/layouts/BaseLayout.astro` (показ баланса), `src/lib/outbid-notice.ts` (клиентский `Math.ceil(price*1.1)` для кнопки перекупа), `src/lib/supabase.ts` (`buyLotShared`, триггер считает цену). Зафиксировать полный список точек чтения/записи баланса и цены.

Ассет: ответ-список «файл:строка — что делает — что переезжает» прямо в тикете.

## Answer

Инвентаризация по текущему `main` (только факты, решений нет). Баланс живёт в localStorage (`pivkoiny_balance`, старт 1000); серверная цена уже авторитетна для самой покупки (триггер считает +10%, клиентский INSERT только `{lot_id, buyer_uid}`), но локальный баланс и гейт доступности — нет.

Хранилище и примитивы:

- `src/lib/wallet.ts:5-6` — `BALANCE_KEY='pivkoiny_balance'`, `START_BALANCE=1000`. Переезжает: всё (источник истины → БД на Auth UID).
- `src/lib/wallet.ts:12-21` — `getBalance()` читает/инитит localStorage. Читатели ниже. Переезжает: чтение → select баланса из БД.
- `src/lib/wallet.ts:23-24` — `canAfford(price)` локальный гейт. Переезжает: гейт → сервер (итоговая цена известна только триггеру; клиентский гейт по протухшей цене врёт).
- `src/lib/wallet.ts:28-31` — `spend(price)` декремент localStorage. Переезжает: списание → сервер в одной транзакции с покупкой/спином.
- `src/lib/wallet.ts:35-41` — `earn(amount)` инкремент localStorage. Переезжает: начисление → сервер (RNG и гранты на бэке).

Чтение/показ баланса (все три — один и тот же localStorage, три дубли render):

- `src/layouts/BaseLayout.astro:45-49` — бейдж `[data-wallet-balance]` в шапке (дефолт `1000` в разметке). Переезжает: значение → из БД.
- `src/layouts/BaseLayout.astro:62-73` — `render()` + `storage`-подписка на `BALANCE_KEY` (синк между вкладками). Переезжает: синк → Realtime/рефетч баланса.
- `src/components/BuyModal.astro:309-314` и `:453` — свой `renderBalances()` + вызов при старте. Переезжает: туда же.
- `src/components/GambaModal.astro:196-201` — свой `renderBalances()`. Переезжает: туда же.

Покупка (двойная бухгалтерия — главный дефект):

- `src/components/BuyModal.astro:350,364-370` — цена намерения берётся из `data-lot-price` кнопки (может протухнуть между рендером и кликом). Переезжает: цена намерения → свежий select перед confirm (тикет 06).
- `src/components/BuyModal.astro:377-381` — `canAfford(price)` по протухшей цене решает «хватит/не хватит». Переезжает: гейт → сервер.
- `src/components/BuyModal.astro:404-406` — `buyLotShared(id)` возвращает серверный `price_paid`; `celebrate` списывает локально уже серверную сумму (`spend(paid)`), т.е. дебет сошелся с сервером случайно, а гейт — нет. Переезжает: списание → сервер; клиент только отображает.
- `src/components/BuyModal.astro:383-386` — без настроенного supabase покупка чисто локальная (`celebrate` без сервера). Решить в спеке: оставить ли деградацию или требовать сессию (кандидат в туман «гости/офлайн»).
- `src/lib/supabase.ts:376-397` — `buyLotShared`: resolve slug→id, INSERT `{lot_id, buyer_uid}`, ответ `price_paid/buyer_login`. Уже сервер-авторитетно по цене; не хватает только денег (баланса) в той же транзакции.
- `src/lib/supabase.ts:269-277` — контракт: цену, identity, паузу 30с, кап 10/10мин считает BEFORE-триггер. Образец для переноса денег: тот же триггер/RPC-стиль.

Гамба (RNG и гранты на клиенте — читерски правится из консоли):

- `src/components/GambaModal.astro:227-228` — исход `Math.random()` 50/40/10 в браузере. Переезжает: RNG → бэк (server-authoritative спин).
- `src/components/GambaModal.astro:268-275` — `earn(1000)` / `earn(100000)` на выигрыше. Переезжает: грант → бэк единой записью со спином (идемпотентность — в туман).
- `src/components/GambaModal.astro:27,59-72` — шансы и номиналы зашиты в разметку/сегменты колеса. Переезжает: таблица выплат → конфиг бэка (клиент только рисует то, что отдал сервер).
- Кнопка `data-gamba-button` (`src/layouts/BaseLayout.astro:38-44`, слушатель `src/components/GambaModal.astro:284-290`) — только открывает модалку, денег не трогает; не переезжает.

Перекуп (клиент дублирует серверную формулу):

- `src/lib/outbid-notice.ts:83,291` — `Math.ceil(ev.price*1.1)` для текста и кнопки; `:96-98` — кладёт результат в `data-lot-price`, дальше см. дефект покупки выше. Переезжает: next-цена → из БД (тикет 06); клиент не считает.
- `src/pages/lots/index.astro:127-161` — витрина уже тянет shared-цену (`fetchSharedLots` + подписка) и обновляет карточку и `data-lot-price`. Образец для кнопки перекупа: тот же механизм.

Итого переезжает на бэк: хранение баланса, гейт доступности, списание/начисление, RNG спина, таблица выплат, next-цена перекупа, межвкладочный синк. Остаётся на клиенте: показ чисел, открытие модалок, делегированные клики, звуки/анимации.
