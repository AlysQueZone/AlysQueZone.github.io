# 01: Публичный профиль: данные, паспорт, страница

**What to build:** У каждого аккаунта появляется публичная страница профиля по `/profile/?uid=<uuid>`: паспорт с логином, датой регистрации, балансом, капиталом («Баланс + приветы») и числом приветов. Данные читаются одним публичным RPC; журнал движений Пивкойнов и служебные поля остаются закрытыми.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] В `profiles` появляется `login`, бэкфилл из метаданных Supabase Auth; триггер обновляет логин при вставке и обновлении метаданных `auth.users`.
- [ ] Публичный read-only RPC `public_profile(uid)` возвращает `user_id`, `login`, `balance`, `created_at`, `capital`, `lots_count`; `capital` считается как баланс плюс текущие цены приветов во владении.
- [ ] `anon` и `authenticated` могут вызвать RPC и прочитать только публичные колонки `profiles`; `updated_at` и `ledger` недоступны.
- [ ] Гость открывает `/profile/?uid=<uid>` и видит `@login`, «На бирже с …», баланс, «Баланс + приветы» и число приветов.
- [ ] Свой профиль показывает «Выйти»; выход завершает сессию и уводит на главную.
- [ ] Неизвестный, битый или отсутствующий uid показывает «Профиль не найден» внутри страницы, с дорогой на биржу.
- [ ] Ошибка чтения показывает честное «Не загрузилось» с кнопкой повтора; загрузка — скелетон.
- [ ] Десктоп: паспорт слева и липкий; телефон: паспорт сверху; страница не разъезжается.
- [ ] Чистое ядро профиля (ссылка по uid, разбор uid, маппинг статов, формат даты и чисел) покрыто тестами; `pnpm build` не ходит в БД.
- [ ] Проверено в `preview` на десктопе и телефоне, залогиненным и гостем; RLS-проверка — на локальном Supabase.
