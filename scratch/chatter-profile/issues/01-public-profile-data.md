# 01: Публичный профиль: данные, паспорт, страница

**What to build:** У каждого аккаунта появляется публичная страница профиля по `/profile/?uid=<uuid>`: паспорт с логином, датой регистрации, балансом, капиталом («Баланс + приветы») и числом приветов. Данные читаются одним публичным RPC; журнал движений Пивкойнов и служебные поля остаются закрытыми.

**Blocked by:** None (can start immediately).

**Status:** resolved

- [x] В `profiles` появляется `login`, бэкфилл из метаданных Supabase Auth; триггер обновляет логин при вставке и обновлении метаданных `auth.users`.
- [x] Публичный read-only RPC `public_profile(uid)` возвращает `user_id`, `login`, `balance`, `created_at`, `capital`, `lots_count`; `capital` считается как баланс плюс текущие цены приветов во владении.
- [x] `anon` и `authenticated` могут вызвать RPC и прочитать только публичные колонки `profiles`; `updated_at` и `ledger` недоступны.
- [x] Гость открывает `/profile/?uid=<uid>` и видит `@login`, «На бирже с …», баланс, «Баланс + приветы» и число приветов.
- [x] Свой профиль показывает «Выйти»; выход завершает сессию и уводит на главную.
- [x] Неизвестный, битый или отсутствующий uid показывает «Профиль не найден» внутри страницы, с дорогой на биржу.
- [x] Ошибка чтения показывает честное «Не загрузилось» с кнопкой повтора; загрузка — скелетон.
- [x] Десктоп: паспорт слева и липкий; телефон: паспорт сверху; страница не разъезжается.
- [x] Чистое ядро профиля (ссылка по uid, разбор uid, маппинг статов, формат даты и чисел) покрыто тестами; `pnpm build` не ходит в БД.
- [x] Проверено в `preview` на десктопе и телефоне, залогиненным и гостем; RLS-проверка — на локальном Supabase.

## Comments

Реализовано: миграция `20261125120000_profiles_public_profile.sql` (`profiles.login`, бэкфилл из метаданных Auth, триггер на `auth.users`, RPC `public_profile`, колонки-гранты), чистое ядро `src/lib/profile.ts`, транспорт `src/lib/profile-read.ts`, страница `src/pages/profile/index.astro` с паспортом, скелетоном, «Профиль не найден» и «Не загрузилось» с повтором.
Проверено: локальный Supabase — гость и authenticated читают только `user_id, login, balance, created_at`, `updated_at` и `ledger` закрыты, логин синкается изменением метаданных, старые счета не потеряны; preview — гость/свой профиль, неизвестный и битый uid, обрыв RPC, десктоп и телефон.
