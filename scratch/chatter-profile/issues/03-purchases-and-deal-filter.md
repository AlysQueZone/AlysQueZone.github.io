# 03: История покупок на профиле и фильтр лога по чатерсу

**What to build:** На профиле видны последние пять покупок и ссылка «Вся история →» на существующий лог сделок. Лог получает фильтр `?user=<uid>` по покупателю и заголовок «Покупки @nick», без новой страницы и новых кнопок.

**Blocked by:** 01 — Публичный профиль: данные, паспорт, страница.

**Status:** resolved

- [x] Профиль показывает последние пять покупок: дата, название привета и цена; строка ведёт на страницу привета.
- [x] «Вся история →» ведёт на `/deals/?user=<uid>`; полная история открывается в существующем логе.
- [x] Лог с `?user=<uid>` показывает только покупки этого покупателя, с листанием и живыми обновлениями.
- [x] Заголовок лога в этом состоянии — «Покупки @nick»; если логин не найден, честный фолбэк без выдуманного ника.
- [x] Кнопки «Все» и «Мои покупки» остаются единственными выходами и сбрасывают `user`; новых кнопок нет.
- [x] Возврат к фильтру чатерса после «Все» работает браузерной «назад».
- [x] Гость может открыть фильтр по чужому uid; «Мои покупки» без входа по-прежнему показывает подсказку.
- [x] Пустое состояние и ошибка чтения выглядят как в существующем логе.
- [x] Чистое ядро фильтра (разбор `?user`/`?mine`, buyer uid, заголовок, URL) покрыто тестами.
- [x] Проверено в `preview`: переход с профиля, листание, «Все», «Мои покупки», пустой и неизвестный uid.

## Comments

Реализовано: чистое ядро `src/lib/deal-filter.ts` (`parseDealFilter`, `buyerUidFor`, `dealFilterUrl`, `dealFilterTitle`), состояние `?user=<uid>` в `/deals/` с заголовком «Покупки @nick» и честным фолбэком, `popstate` для возврата браузерной «назад», «Все»/«Мои покупки» сбрасывают фильтр; на профиле — пять последних покупок с датой, названием и ценой, строки ведут на привет, «Вся история →» на `/deals/?user=`.
Проверено: гость и залогиненный, листание и live, пустой и неизвестный uid, ошибка чтения, мобильная и десктопная раскладки, «Вся история →» остаётся видимой при ошибке превью.
