## Question

Какой SQL-гайд принимаем для Supabase (стиль миграций, нейминг таблиц/колонок, RLS-политики, правила про DROP VIEW + CREATE вместо CREATE OR REPLACE)? Учесть, что схему меняем только миграциями, а очередь применяет их при мерже в main.

## Answer

- Русская шапка-комментарий обязательна для каждой миграции (что/зачем/инварианты/как применяется, руками на прод не накатывать).
- RLS deny-by-default обязателен: `revoke all`, затем точечные grant/policy; записи только сервером, где возможно.
- Нейминг фиксирован: таблицы plural snake_case, индексы `<table>_<cols>_idx`, политики `<table>_<действие>_<скоуп>`, конфиги single-knob. Плюс действующее: схему только миграциями, вью с изменением колонок — только `DROP VIEW + CREATE`.
