# 08: Сетка карточек — общий план набора и заметки

Status: ready-for-agent

Тикет: [08-lot-grid](../issues/08-lot-grid.md)
Ревью: [review.md](../review.md), карточка «Reconcile карточек на двух поверхностях».

## Problem Statement

Две поверхности рисуют **Карточки Лота** из снапшота: витрина `/lots/` и главная. Витрина умеет добавлять новые карточки по цене, главная — только перекрашивать уже показанные. Поэтому главная не добирает новые карточки, а две реализации reconcile уже разошлись. Заметки состояний (`loading / empty / failed`) тоже собираются двумя похожими тернарниками.

ADR-0009 прямо отклонил «модуль владеет reconcile»: создание, удаление и сортировка DOM — забота поверхности. Но чистый план «добавить / убрать / оставить» — не DOM-reconcile, и его можно вынести, не переоткрывая ADR.

## Solution

Новый чистый `lot-grid.ts` считает план набора и состояние заметки. Поверхности по-прежнему владеют DOM: создают клон **Карточки Лота**, заполняют через `fillLot`, вставляют/удаляют и держат `rendered`. Витрина вставляет добавленные карточки по цене, главная — в порядке своей выборки.

Расхождение главной воспроизводится тестом плана и чинится переходом на `planGrid`: главная начинает добавлять недостающие карточки из своего окна, а не только перекрашивать старые.

## User Stories

1. Как чатерс, я хочу видеть на витрине все **Карточки Лота** из окна, чтобы не пропустить доступные **Лоты**.
2. Как чатерс, я хочу, чтобы новая **Карточка Лота** появлялась на витрине в порядке цены, чтобы дешёвые **Лоты** были первыми.
3. Как чатерс, я хочу, чтобы исчезнувшая **Карточка Лота** убиралась, чтобы сетка не показывала проданное.
4. Как чатерс, я хочу, чтобы главная добирала новые **Карточки Лота** из своей выборки, чтобы секция не пустела после удаления.
5. Как чатерс, я хочу, чтобы главная не пересобирала уже показанные карточки, чтобы они не прыгали под курсором.
6. Как чатерс, я хочу видеть честную заметку «пусто» или «не загрузилось», чтобы отличать отсутствие **Лотов** от сбоя.
7. Как чатерс, я хочу, чтобы скелетоны исчезали после первого ответа БД, чтобы не было вечной загрузки.
8. Как мейнтейнер, я хочу один чистый план add/remove/keep, чтобы две поверхности не расходились.
9. Как мейнтейнер, я хочу, чтобы план не знал DOM, чтобы его можно было тестировать без браузера.
10. Как мейнтейнер, я хочу, чтобы режим «сортировка по цене» и «фиксированная выборка» оставался у поверхности, чтобы ADR-0009 не переоткрывался.
11. Как мейнтейнер, я хочу общий `gridNote`, чтобы `empty` и `failed` решались один раз, а текст оставался у поверхности.
12. Как мейнтейнер, я хочу тест на расхождение главной, чтобы «не добирает новые» не вернулось.
13. Как релиз-владелец, я хочу пройти `just test`, `just check` и клик по обеим сеткам, чтобы поведение не изменилось, кроме исправленного добора.

## Implementation Decisions

- Новый `lot-grid.ts` — чистый модуль без DOM и `live`.
- `planGrid(currentSlugs, nextStates)`:
  - вход: текущие slug в порядке DOM и следующие состояния в порядке показа;
  - выход: `{ remove: string[]; keep: string[]; add: LotState[] }`;
  - `remove` — slug, которых нет в `nextStates`;
  - `keep` — slug, которые есть в обоих;
  - `add` — новые состояния в порядке `nextStates`;
  - состояния с нечисловой ценой отбрасываются (как сейчас в reconcile);
  - дубли slug в `nextStates` схлопываются по первому вхождению.
- `gridNote(known, ok, count)` → `'loading' | 'ok' | 'empty' | 'failed'`:
  - `!known` → `loading`;
  - `known && !ok && count === 0` → `failed`;
  - `known && ok && count === 0` → `empty`;
  - иначе → `ok`.
- Витрина `/lots/`: `rendered` (slug → node) остаётся; `render()` получает план, удаляет `remove`, заполняет `keep` и `add` через `fillCard`, вставляет `add` через существующий `insertSorted` по цене. `clearSkeletons`, `setGridNote`, `setStatus`, тексты — остаются.
- Главная: `rendered` остаётся; `render()` получает план, удаляет `remove`, заполняет `keep` и `add`; `add` вставляется в порядке выборки (append/`replaceChildren` только для первой непустой выборки). `painted` больше не блокирует добор: после первой отрисовки план может добавить недостающую карточку.
- `insertSorted` остаётся у витрины: это её режим размещения, не общий план.
- `clearSkeletons` остаётся локальным DOM-хелпером поверхности (разные корни/маркеры). `setStatus` / `setNote` и тексты `FAIL_TEXT` / пусто — свои у поверхности; общий только `gridNote`.
- `fillLot`, `LotState`, `live.catalog()` / `catalogWindow()` не меняются этой карточкой (переименование `catalog()` в `catalogMap()` — тикет 09).
- Раскладка кадра (`lot-video` / `lot-view` / `orientationOf`) в карточку не входит: ADR-0009 уже назначает раскладку `lot-view`, отдельный тикет — если шов вырастет.

## Testing Decisions

Хороший тест — через чистый план: slug и состояния на входе, add/remove/keep на выходе; без DOM. Prior art — `trade-history.test.ts`.

- `lot-grid.test.ts`:
  - пустой текущий + непустой next → все в `add`, `remove`/`keep` пусты;
  - непустой текущий + пустой next → все в `remove`;
  - общий набор → `keep`, без add/remove;
  - новый slug в next → `add` в порядке next;
  - дубли slug в next → один add;
  - нечисловая цена → состояние отброшено;
  - `gridNote`: loading / ok / empty / failed.
- Расхождение главной: `[a,b,c,d]` → `[a,b,c]` даёт `remove d`; `[a,b,c]` → `[a,b,c,e]` даёт `add e`. Это фиксирует поведение, которого сейчас нет у `painted/refill`.
- DOM, сортировка вставки и заметки проверяются кликом в `preview`; юнит-тестов на DOM нет.

## Out of Scope

- Переоткрытие ADR-0009 и перенос DOM-reconcile в модуль.
- Изменение политики случайной выборки главной (`random_lots`) и ADR-0012.
- Раскладка кадра, `lot-video`, `orientationOf`, CSS `:has`.
- Общий DOM-хелпер `toggle` / `clearSkeletons`.
- Изменение `fillLot`, `LotState`, `live` и запросов каталога.
- Новые тексты заметок.

## Further Notes

- ADR-0009 отклонял именно «модуль владеет reconcile списка (создание/удаление/сортировка)». `planGrid` не создаёт и не удаляет узлы; он только говорит, что сделать. Это сохраняет решение ADR.
- Главная использует `catalog()` (карту) для поиска исчезнувших карточек и `catalogWindow()` для порядка. После тикета 09 `catalog()` станет `catalogMap()`; эта карточка не должна ждать переименования.
- Текущий `painted/refill` главной не добавляет новые карточки; план делает добор явным и тестируемым.
- Витрина уже добавляет новые карточки; переход на план не должен менять её порядок вставки.

## ADR impact

`none`. ADR-0009 сохраняется: представление одной **Карточки Лота** остаётся в `lot-view`, DOM-reconcile — у поверхности. `planGrid` — чистый план, а не владелец reconcile. ADR-0012 сохраняется: срез главной остаётся случайной выборкой.

## Seams / test surfaces

- Новый чистый шов — `lot-grid` (`planGrid`, `gridNote`); единственная новая тестовая поверхность.
- Существующий шов представления — `lot-view.fillLot`; не меняется.
- Существующий шов снапшота — `live.catalog()` / `catalogWindow()`; не меняется.
- DOM-цикл, `rendered`, `insertSorted`, `clearSkeletons` остаются у поверхностей.

## Task graph

Одна сессия исполнения.

1. `lot-grid.ts` + тесты плана и заметки, включая расхождение главной.
2. Витрина `/lots/`: переход на `planGrid`, сохранение `insertSorted`.
3. Главная: переход на `planGrid`, добор новых карточек, удаление `painted`-блокировки.
4. Гейты и клик по обеим сеткам.

Шаги 2 и 3 зависят от 1; между собой независимы.

## Acceptance gates

- `just test` — тесты плана проходят.
- `just check` — типы, линт, формат, тесты, сборка.
- `just preview` + клик: витрина добавляет/удаляет **Карточки Лота** и держит порядок по цене; главная добирает новую карточку после удаления; заметки «пусто»/«не загрузилось» честные; скелетоны исчезают.
- Коммит; запись в `CHANGELOG.md` в группе `### Внутри`.

## Glossary terms

- **Карточка Лота** — представление **Лота** в сетке: заголовок, кадр, бейджи, кнопка **Покупки**.
- **Лот** — привет, который торгуется на **Бирже**.
- **Биржа** — витрина перепродаж **Лотов**.
- **Покупка** — запись сделки; кнопка **Карточки Лота** ведёт в **Окно** **Покупки**.
