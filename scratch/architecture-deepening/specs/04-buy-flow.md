# 04: Покупка — чистое ядро фаз и ошибок

Status: ready-for-agent

Тикет: [04-buy-flow](../issues/04-buy-flow.md)
Ревью: [review.md](../review.md), карточка «Поток покупки заперт в BuyModal».

## Problem Statement

**Окно** покупки держит семь независимых забот: гость и сессия, **Пауза** с таймером, лимит окна, «идёт **Покупка**», проекция **Паузы** чтением **Истории перепродаж**, проекция цены из снапшота и возврат из логина. Фазы (`idle / guest / pause / limit / busy / confirm`) нигде не названы: они выводятся из семи переменных замыкания. `mapBuyError` спрятан за `buyLot`, который ходит в сеть, поэтому таблицу «ошибка → вид» нельзя проверить без **Покупки**.

Для чатерса поведение выглядит правильным, пока всё работает. Цена сопровождения — невозможность покрыть деньгами и **Паузой** без DOM и риск разъехания фаз при следующей правке.

## Solution

Новый чистый `buy-core.ts` — редьюсер фаз и ошибок с инъекцией часов. Он получает события `intent / refreshed / tick / result / close` и возвращает новое состояние и типизированные эффекты. **Окно** покупки остаётся адаптером: разметка, тексты, **Всплывающие уведомления**, confetti, видео, таймер, сеть, live-подписки, сессия и `pending-buy`.

`mapBuyError`, `BuyErrorKind` и `BuyResult` переезжают в ядро; `buyLot` остаётся сетевой функцией и импортирует эти типы. `buy-intent` остаётся единственным владельцем намерения (ADR-0004).

## User Stories

1. Как чатерс, я хочу открыть **Окно** **Покупки** и увидеть цену и владельца **Лота**, чтобы решить, забирать ли его.
2. Как чатерс, я хочу видеть «Не хватает Пивкойнов», когда баланса меньше цены, чтобы не нажимать зря.
3. Как гость, я хочу видеть вход через Twitch вместо кнопки **Покупки**, чтобы понимать, что нужно для **Покупки**.
4. Как чатерс, я хочу видеть честный отсчёт **Паузы**, чтобы знать, когда можно забрать **Лот** повторно.
5. Как чатерс, я хочу видеть лимит окна после `rate-limit`, чтобы не жать кнопку вслепую.
6. Как чатерс, я хочу, чтобы во время **Покупки** кнопка была занята, чтобы не отправить второй запрос.
7. Как чатерс, я хочу, чтобы **Пауза** проецировалась из моей последней **Покупки** этого **Лота**, чтобы таймер был честным после перезагрузки.
8. Как чатерс, я хочу, чтобы цена в открытом **Окне** обновлялась по живому снапшоту, чтобы **Перекуп** не стал сюрпризом.
9. Как чатерс, я хочу вернуться к тому же **Лоту** после логина, чтобы не искать его снова.
10. Как чатерс, я хочу, чтобы `unauthenticated` переводил **Окно** в гостевой режим, а не показывал общую ошибку.
11. Как чатерс, я хочу, чтобы `cooldown` запускал **Паузу**, а `rate-limit` — лимит, чтобы вид ошибки совпадал с состоянием кнопки.
12. Как мейнтейнер, я хочу одну таблицу фаз и переходов, чтобы поведение кнопки не выводилось из семи переменных.
13. Как мейнтейнер, я хочу `mapBuyError` в чистом ядре, чтобы покрыть все виды ошибок без сети.
14. Как мейнтейнер, я хочу инъекцию часов, чтобы **Пауза** и `tick` тестировались без реального времени.
15. Как мейнтейнер, я хочу, чтобы `buy-intent` оставался единственным владельцем намерения, чтобы не появился второй формат `data-buy-intent`.
16. Как мейнтейнер, я хочу, чтобы навигация `pending-buy` не входила в ядро **Покупки**, чтобы чистый редьюсер не знал про URL и `sessionStorage`.
17. Как релиз-владелец, я хочу пройти `just test`, `just check` и клик по **Окну** **Покупки**, чтобы деньги и **Пауза** работали как раньше.

## Implementation Decisions

- Новый `buy-core.ts` экспортирует `BuyPhase`, `BuyState`, `BuyEvent`, `BuyEffect`, `createBuyCore`, `mapBuyError`, `pauseRemainingSec`, `BuyErrorKind`, `BuyErrorInfo`, `BuyResult`.
- Фазы: `idle | guest | pause | limit | busy | confirm`.
- Состояние: `phase`, `intent`, `balance`, `pauseLeft`; `pauseLeft` — секунды, не дедлайн.
- События:
  ```ts
  type BuyEvent =
    | { type: 'intent'; intent: BuyIntent; guest: boolean }
    | { type: 'refreshed'; balance?: number | null; price?: number | null; owner?: string }
    | { type: 'tick' }
    | { type: 'result'; result: BuyResult }
    | { type: 'close' };
  ```
- `createBuyCore({ now })` возвращает `state()` и `dispatch(event): BuyEffect[]`. Ядро не ставит таймеров и не читает `Date.now()` само.
- `intent`: гость → `guest`, иначе → `confirm`; намерение сохраняется. `refreshed`: обновляет баланс, цену и владельца; не затирает `pause` / `limit` / `busy`. `close`: сбрасывает в `idle`.
- `result`:
  - `ok` → `idle`, эффекты `celebrate(paid)` и `close`;
  - `cooldown` → `pause`, `pauseLeft = retryAfterSec ?? 30`, эффект `pauseTimer(seconds)`;
  - `rate-limit` → `limit`, эффект `limit` (кнопка держит лимит до закрытия);
  - `insufficient-funds` → `idle`, эффекты `close` и `notice`;
  - `unauthenticated` → `guest`, без авто-редиректа;
  - `own-lot` / `missing-lot` / `price-cap` / `offline` / `write-error` → `confirm`, эффект `notice(kind)`.
- `tick` действует только в `pause`: уменьшает `pauseLeft` по инъектированным часам; на нуле → `confirm` и эффект `refreshPrice(slug)`.
- `pauseRemainingSec(boughtAt, now, pauseSec = 30)` — чистая функция: `ceil(pauseSec - (now - boughtAt) / 1000)`, не меньше нуля; битая дата → `0`.
- `mapBuyError` и `parseCooldownSec` переезжают из `lots.ts` без изменения таблицы: `cooldown`, `rate-limit`, `own-lot`, `unauthenticated`, `missing-lot`, `price-cap`, `insufficient-funds`, `offline`, `write-error`. Запасная **Пауза** — 30 с.
- `lots.ts` оставляет `buyLot` (свежая цена, `buyLotShared`, `live.reportPurchase`) и импортирует `BuyResult` / `mapBuyError` из `buy-core`; приватный классификатор удаляется.
- `BuyModal` остаётся адаптером: DOM, тексты, `showSpotNotice`, `boom`, видео, `setInterval`, `fetchSharedHistory`, live-подписки, чтение сессии, `pending-buy`, вызов `buyLot`.
- **Пауза**: компонент читает последнюю свою **Покупку** через `fetchSharedHistory`, передаёт `boughtAt` в `pauseRemainingSec` и шлёт `tick` по таймеру; при закрытии **Окна** таймер снимается, ядро получает `close`.
- **Возврат из логина**: `pending-buy` / URL / ожидание кнопки остаются в компоненте; в ядро приходит уже восстановленное намерение.
- `buy-intent` не меняется: `BuyIntent`, `buyAvailability`, `readBuyIntent`, `writeBuyIntent` остаются его интерфейсом; ядро не дублирует разбор.
- Тексты «вид ошибки → строка» остаются в компоненте; ядро отдаёт вид и `retryAfterSec`.

## Testing Decisions

Хороший тест — через редьюсер: событие на входе, состояние и эффекты на выходе; без DOM и сети. Prior art — табличные тесты `trade-history` и `buy-intent`.

- `buy-core.test.ts`:
  - `intent` гостем → `guest`; залогиненным → `confirm`;
  - `refreshed` обновляет баланс/цену/владельца и не затирает `pause` / `limit` / `busy`;
  - `tick` уменьшает `pauseLeft` по fake clock; на нуле → `confirm` + `refreshPrice`;
  - `close` сбрасывает в `idle`;
  - каждый `result`: `ok`, `cooldown` (с `retryAfterSec` и без), `rate-limit`, `insufficient-funds`, `unauthenticated`, `own-lot`, `missing-lot`, `price-cap`, `offline`, `write-error`;
  - `pauseRemainingSec`: остаток, ноль, битая дата;
  - `mapBuyError`: все виды и парсинг `cooldown` (`hms`, секунды, фолбэк 30).
- Тесты не дублируют `buy-intent`: его таблица остаётся в `buy-intent.test.ts`.
- **Окно** покупки, `pending-buy`, live-подписки и тексты проверяются кликом в `preview`, не юнит-тестами.

## Out of Scope

- Сеть, `buyLotShared`, серверные триггеры и формула цены.
- Разметка **Окна**, тексты, **Всплывающие уведомления**, confetti и видео.
- `pending-buy` и возврат из логина как навигация.
- `buy-intent`: формат намерения и `buyAvailability` не меняются (ADR-0004).
- `mapGambaError` и **Церемония** **Гамбы** — отдельная карточка.
- Новые виды ошибок или изменение серверных текстов.

## Further Notes

- `BuyModal` сейчас читает сессию и `pending-buy` напрямую; после тикета 02 импорты `getSupabase` и `pending-buy` идут из новых модулей, но поведение не меняется.
- Ядро не знает, откуда пришло `refreshed`: из live-события, из явной свежести или из возврата вкладки. Это делает его независимым от транспорта.
- `busy` — транзитное состояние на время `buyLot`; компонент ставит его перед вызовом и снимает по `result`. Ядро не вызывает сеть.
- Если `insufficient-funds` приходит при открытом **Окне**, текущее поведение закрывает **Окно** и показывает **Всплывающее уведомление**; ядро сохраняет это как эффекты `close` + `notice`.

## ADR impact

`none`. ADR-0004 (намерение **Покупки** — один слот `data-buy-intent`) не переоткрывается; ядро только импортирует его тип и правило доступности. ADR-0003 не задет: живые данные по-прежнему приходят через `live`.

## Seams / test surfaces

- Новый чистый шов — `buy-core` (редьюсер, `mapBuyError`, `pauseRemainingSec`); единственная новая тестовая поверхность.
- Существующий шов намерения — `buy-intent`; не меняется.
- Существующий шов сети — `buyLot` / `buyLotShared`; остаётся адаптером.
- DOM, таймер и live-подписки остаются у **Окна** покупки.

## Task graph

Одна сессия исполнения.

1. `buy-core.ts`: типы, редьюсер, `mapBuyError`, `pauseRemainingSec` + табличные тесты.
2. `lots.ts`: импорт типов и классификатора из ядра, удаление приватной копии.
3. `BuyModal`: перевод на `dispatch` + эффекты, таймер/сеть/live остаются; тексты и разметка не меняются.
4. Гейты и клик по **Окну** **Покупки**.

Шаги 2 и 3 зависят от 1; между собой независимы.

## Acceptance gates

- `just test` — новые табличные тесты ядра проходят.
- `just check` — типы, линт, формат, тесты, сборка.
- `just preview` + клик: гость видит вход; залогиненный видит цену и владельца; «не хватает» гаснет; **Пауза** тикает; `rate-limit` показывает лимит; ошибка не ломает **Окно**. **Покупку** делать только при наличии тестового аккаунта.
- Коммит; запись в `CHANGELOG.md` в группе `### Внутри`.

## Glossary terms

- **Покупка** — запись сделки; цену, **Паузу** и гейт **Пивкойнов** считает сервер.
- **Перекуп** — повторная **Покупка** **Лота**.
- **Пауза** — ожидание перед повторной **Покупкой** того же **Лота**.
- **Окно** — диалог **Покупки** поверх страницы.
- **Всплывающее уведомление** — короткое сообщение об успехе, ошибке или **Паузе**.
- **Лот** — привет, который торгуется на **Бирже**.
- **Пивкойн** — валюта **Биржи**.
