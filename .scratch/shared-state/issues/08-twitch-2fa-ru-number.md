# Twitch 2FA на российский номер

Type: research
Status: resolved

## Question

Twitch Dev Console требует 2FA на аккаунте разработчика, но SMS-регистрация на российский номер падает («Не удалось зарегистрировать двухфакторную аутентификацию»). Выяснить: это системный блок RU-номеров или частная проблема? Что проверить: сигналы 2024–2026 (доставка Twitch-SMS на +7, Хабр/VC/Reddit/форум Twitch), можно ли включить app-based 2FA (Authy/Google Authenticator) БЕЗ привязки телефона, принимает ли Twitch виртуальные/eSIM-номера других стран по правилам, есть ли обход без нарушения ToS. Выход — вердикт + рабочий путь регистрации Twitch-приложения для нашего кейса (блокер прототипа общей покупки).

## Answer

Вердикт: системный блок, не частная проблема. Twitch официально: Россия — единственный регион, заблокированный для SMS 2FA (help-статьи EN/RU), отключение с 22.03.2023; RU-юзерам предписано приложение-аутентификатор. Подвох: штатный флоу всё равно требует SMS-шаг первым («SMS verification is always required first»), поэтому +7 не проходит никак — VPN/повторы не лечат (блок по коду страны, не по IP/оператору). Рабочий путь: десктопный браузер → verified email → SMS-шаг на НЕ-российский real-SIM номер (SIM знакомых за рубежом > travel-eSIM с SMS > долгосрочная аренда non-VoIP; не Google Voice/одноразовые shared-пулы) → на экране QR сразу привязать TOTP-приложение + сохранить secret → вход по TOTP, номер оставить как recovery-якорь → dev.twitch.tv/console пропустит. Запасной: другой не-RU номер / пауза 24ч при rate-limit / тикет в Twitch Support со ссылкой на их RU-статью / одолжить номер на 10 минут. Прямого запрета виртуальных номеров в ToS нет, банятся обход банов и боты. Полный разбор с шагами — в истории сессии research (subagent ses_f89dfc838ffeqo0trRNt05uGz5).

## Comments

- 2026-09-06: Q — прокатит ли отдельный dev-аккаунт на «одноразовом телефоне»? A — сам по себе отдельный аккаунт под dev — нормальная практика (разделение; запрещён обход банов, а не второй аккаунт). Но «одноразовый» = два разных исхода: бесплатный public-inbox/shared-пул — почти наверняка нет (VoIP/shared в бан-списках, «номер уже привязан», коды видит весь интернет, номер перевыпустят → угон dev-аккаунта через восстановление); долгосрочная аренда real-SIM non-VoIP на месяцы — да, рабочий вариант. В обоих случаях сразу привязать TOTP и сохранить secret, номер держать как recovery-якорь весь срок жизни приложения.
