# Twitch-auth с минимальным скопом

Type: research
Status: resolved

## Question

Можем ли мы без особых усилий прикрутить auth через Twitch с минимальным скопом (только ник чатерса, без email и прочего)? Что проверить: поток OAuth для чистой статики без своего сервера (implicit deprecated? Auth Code + PKCE из браузерного JS?), минимальный скоп (`openid` / `user:read:email` не просим), валидация токена без бэкенда, вариант через Supabase Auth Twitch-провайдер (колбэки, сессии в supabase-js на GitHub Pages), регистрация приложения в Twitch Dev Console (что нужно: client ID в клиенте — ок, секрет — куда?), стабильность identity (Twitch user id vs login при смене ника), условия усилия: 0₽, открытие из РФ без VPN (и `id.twitch.tv`, и Supabase Auth), оценка трудозатрат в часах/шагах. Выход — вердикт «берём / не берём» + какая identity ложится в shared-историю.

## Answer

Вердикт: условно берём — опциональный вход через Supabase Auth Twitch-провайдер + гибрид с гостями; обязательный логин нельзя (фрикшн входа убьёт шутку). Факты: PKCE Twitch не поддерживает, прямой Auth Code из статики невозможен (нужен client_secret) — только через Supabase Auth (секрет живёт в Supabase, браузер ходит редиректами); скоп пустой или `openid`, email не нужен; identity = стабильный Twitch user_id (sub, цифры), login — только снапшот для показа; регистрация app бесплатна, нужна 2FA на аккаунте разработчика; 0₽ (Supabase Free: 50k MAU), формального блока Twitch/Supabase из РФ нет (проверить три URL из RU без VPN); усилия ~4–6ч; риски: redirect-матчинг в 3 местах, пауза Free-проекта после 7 дней тишины, секрет никогда во фронт.
